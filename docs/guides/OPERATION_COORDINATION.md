# 并行规划、施工与任务接取

本文规定当前由执行者安排的协作流程。**当前没有覆盖全流程的统一任务调度器、共享预算或运力预留器，也不会在施工时自动暂停游戏或自动停止接取补贴。** 基本操作规则见[执行手册](AGENT_PLAYBOOK.md)，补贴接口见[任务说明](../reference/SUBVENTIONS.md)。

## 1. 已有保护与适用范围

| 当前保护 | 保护什么 | 不保证什么 |
|---|---|---|
| 文件桥接请求锁 | 序列化单次请求的文件访问 | 调查→预览→提交→验证整个流程不被插入其他操作 |
| 设施／贷款预览及提交校验 | 拒绝部分过期状态、重复令牌与不符合条件的操作 | 所有工具共用同一事务或失败自动回滚 |
| 自动接取轮次锁 | 同一 MCP 进程内 `run_once` 执行串行 | 多服务进程共享决策和资源分配 |
| 补贴待确认阻断 | 未确认原生接取时阻止继续接取 | 其他类型施工、购车或贷款也自动阻断 |

后台自动接取运行中，手动 `run_once` 会被拒绝，应先 `stop`。接口的局部锁不能视为多个 agent 可随意同时改同一地图的依据。

## 2. 哪些工作可以同时做

| 工作组合 | 安排方式 |
|---|---|
| 两份离线方案比较 | 可并行读取同一快照，分别输出，注明同一基线和各自假设 |
| 全局策略与局部布局 | 可分别分析；合并时核对共享用地、走廊、需求和预算 |
| 只读调查与游戏模拟 | 允许，但记录时间与覆盖；提交前重新核对变化的实体 |
| 同一区域的道路、设施、站点建设 | 按依赖串行；上一阶段读回后才产生下一阶段输入 |
| 影响任务运力的改线、卖车、扩建 | 先核对活动任务及依赖，确认服务安排后再执行 |
| 施工与自动接取 | 执行者先停止自动接取、核对 pending，再施工与复核 |

由一个执行者维护当次操作清单：操作对象与位置、前置步骤、预算、共享车辆／站点、活动任务、预览依据、提交状态和读回证据。其他规划提出建议；对共享地图的写入按这份清单排队。

## 3. 建造前后的顺序

1. 确认会话和授权，读取活动任务、自动接取状态及现有线路。已接受任务继续在游戏中计时，停止轮询不会取消任务。
2. 记录自动接取的运行状态、完整 policy、interval 和 dry-run 设置。需要改变其依赖设施或运力时调用 `subvention_autoaccept(action="stop")`；若用户要求其持续运行，应先安排不冲突的工作。
3. 查询原生任务核对已提交操作。`stop` 不能撤回已发送事件；取消时仍可能留有 pending。查不到任务也不证明没有接取。
4. 列出本次会影响的用地、道路、站组、线路、车辆与财务承诺。未解决的冲突阻止依赖它的施工，但可继续独立的只读分析。
5. 按“当前调查→施工前存档→预览→单次提交→读回”推进。路段替换后重新解析实体，不将旧 ID 传给下一步。
6. 重新检查双向路径、装载配置、任务服务和可用能力，更新计划与台账。仅在原授权仍适用、冲突已处理时恢复原自动接取策略；不要使用默认参数覆盖此前约束。

## 4. 是否暂停游戏

普通离线规划不暂停。施工是否暂停取决于步骤是否需要一致性窗口、是否涉及批量替换或受控诊断，并遵循已有授权。记录原速度与暂停原因，完成正常操作后恢复；故障诊断中不自动恢复高速。

暂停不能防止人工编辑，也不能修复旧实体引用。原生任务事件可能需要后续更新才生效，暂停期间等待回执超时不能据此重新发送。暂停更不能作为规避碰撞和断言的手段。

## 5. 冲突与未知结果

| 现象 | 处理 |
|---|---|
| 道路编号、端口或设施配置改变 | 放弃旧预览，按位置与当前组件重新解析 |
| 超时、异常或部分成功 | 保留原请求，读取现场与原生状态，禁止自动重发 |
| 同一线路被多个方案分配全部运力 | 汇总需求，明确每项分配；不足部分列为缺口 |
| 任务接取 pending | 只读核对；不通过服务重启或读档清除记录来绕过 |
| 更换地图或重启服务 | 重新确认会话与原生任务；内存记录丢失不表示任务不存在 |

未来若实现统一协调器，应另行定义流程锁、资源预留、持久化恢复和冲突处理，并完成对应测试后更新本文。现阶段这些属于待实现能力。
