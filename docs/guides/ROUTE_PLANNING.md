# 普通路线规划：按需调查

2026-10-16 规划读取默认批处理：同一依赖轮次内、参数已知且互不依赖的白名单查询，优先调用 `read_planning_data(requests)`，由客户端按每批最多8项及8192字节自动分批。先取得真实城市/实体ID，再发下一轮详情；不为凑批扩大调查范围。逐项检查 `ok` 及子结果 `available/complete`，仅明确的时间/大小限制可缩为单项再读一次；原生错误、超时未知和会话变化不自动重发。已有整包快照保留，白名单外接口继续使用原命名查询，不包装 eval。预览、提交、施工前新鲜读数和独立验收仍按原流程执行，不跨施工复用规划缓存。见[规划批量读取](../reference/READ_BATCH.md)。本规则不启动施工或恢复监控。


2026-10-12 用户确认。默认用于单条线路、小型供给链和既有地图上的局部增补；本规则优先于全图规划流程中的默认调查、精算与交付要求。全图统筹、批量集合建设或用户明确要求的专项优化仍使用对应完整流程。

## 默认流程与停止条件

2026-10-12 用户补充授权：后续可以新建道路以缩短送货时间。已有路线明显绕行时，按需比较必要捷径的配送时间收益、整段费用、两端实际接入和维护覆盖；优先复用不意味着必须接受明显绕行。当前预算、只规划边界和施工验收要求不变，不默认展开所有备选或全图地形调查。

1. 确认当前会话、需求货品、当前余额和可复用设施。账户不足以支撑建设时说明资金限制；只要求路线方向的任务不继续展开施工级选址、报价和原生预览。
2. 先比较现有源头、接驳和道路条件。优先复用，以首个有依据的合理方案为主案；只在明确缺陷、失败或用户要求比较时展开备选，不同时细化所有运输方式。合理包括源头和货品匹配、必要接驳、可用载具与明显资金限制，不能把未知连接称为已验证。
3. 确定运输方式后，只核对候选车型的可用性、货舱兼容、价格和采购基地。已有可靠资源证据可复用，版本或候选改变才重新读取；不默认查询所有载具目录、拆读资源包。
4. 给出供给链、复用设施、必要新增设施、首批载具、费用依据与待确认项后结束。需求数量缺失写未知，不补做逐建筑交付统计，不以人口推算精确需求，不承诺满足率。

## 城市配送卸货站：客货分离与边缘选址（2026-10-13）

线路配置须与站点用途一致：源头装货、目的站卸货，途经站按需保留货品。`loads` 是逐站装载／保留列表，不能把整线货品清单复制到所有站。仅卸货的目的站显式配置 `loads: []`，省略该字段可能保留旧配置；正常卸货使用 `force_unload: false`。多货品、中转及多配送点须逐站核对真实接收能力。详细语义、示例和潮州修复证据见[货运装卸配置](../reference/CARGO_LOADING.md)。

2026-10-16 新增强制约束：前期城市货物配送终点必须使用道路停靠点，不能新建货运车站／货车站作为配送终点。须按实际设施类型、货运终端能力和货品兼容性核实该停靠点支持目标货品卸货，不能把普通公交停靠点当作货运停靠点。此条优先于旧设施模板及一般建造授权，适用范围为城市配送终点，不自动禁止生产源装货点或中转设施。

给城市配送货物的卸货站必须独立设置，不得与公交换乘点共用站点设施、停靠点或装卸/上下客终端；不能仅用不同线路、名称或时段把同一站点视为已分离。规划公交与货运时分别标明设施、终端及接入口，核对实际对象与功能。此约束不要求客货车辆使用完全独立的道路网络。

卸货站尽量布置在该货品实际供应区域的边缘，禁止设置在城市中间道路上。以当前需求建筑分布及原生配送覆盖/接收关系界定供应区域，不按城市名称、几何中心或固定距离猜测覆盖。优先选外围道路侧边或独立货运接入道路，并保留货车进出、转弯及排队空间，避免干扰公交换乘。

边缘选址仍须道路连续通达并实际覆盖目标需求建筑，不能为满足城市边缘位置偏好把停靠点建到无法卸货供货的位置。前期单点覆盖不足时，评估多个独立边缘道路卸货停靠点或必要外围接路，纳入完整费用与原生预览。接口不支持货运道路停靠点、卸货／接收覆盖无法确认或找不到合规方案时，记录具体能力、覆盖、道路或地形缺口，不回退建设货运车站，也不回退到客货共站或城市中间道路卸货；未知能力不得报告为可以卸货。

本规则适用于新建、扩容选址及复用方案审查，优先于旧模板的客货共站或城区中部卸货安排。既有不合规站点记录为待调整，不因文档更新直接拆迁、停运或迁移；实施调整时按有效授权先建成并验收独立替代卸货站，再调整货运线路，保留公交服务。资金、接路、维护、原生预览及城市实际收货验收规则不变。

## 产业道路接入现有路网：规划前置检查（2026-10-13）

规划公路货运、原料接驳或产业工人运输时，先检查每个相关产业的内部客货终端、厂区道路和真实外部接口是否已经接入本线路所用的现有路网，并核对采购车库出口能否进入该运输走廊。新出现产业与既有产业均须检查，不能默认产业自带道路已接通。

分别留下两层证据：设施内部终端到外部接口的连接，以及外部接口经现有道路到线路另一端的连续通达。局部路口通路通过、车库贴路建成、终端支持TRUCK/BUS、道路在画面上相交或相距很近，均不能代替产业接入现有路网的证明。按所选车辆的运输模式和行驶方向，使用当前受支持的原生拓扑/通路读取核实；接口不足以确认时标为待核实，不用购车或反复分配车辆试探。

发现产业道路孤立或接驳缺口，先把必要接路纳入完整方案、费用和依赖顺序；在已有授权内预览、施工并独立读回实际连接，完成后再购车、分配和投运。只规划时明确标出缺口和接路方案。此检查不要求全图扫描、精算最短路或安排车辆完整往返。

用户手动接路后，旧道路引用与相关预览失效；记录用户修复说明，下次实际操作前重新读取受影响的接口、路段与通达。不得重复建路、重复购车或重放已失败的请求，也不能把“用户已接通”记成Agent已完成原生验收。

## 码头资源接驳：优先一终点一线（2026-10-13）

码头到渔船、沙场、油井的运输，优先每个实际资源终点一条独立线路，尽量不把多个终点合并在同一线路或串站服务；各线分别配置兼容运力与装卸，不挪空其他资源线。独立线路不等于必须新建独立码头，配套按实际兼容、通达和拥堵规划。只有独立方案受水路、终端、接口或资金等具体条件制约时才考虑共线，并记录原因及服务安排。详见[水运资源接驳规划](../strategy/TRANSPORT_WATER_SITING.md#资源接驳优先一终点一线2026-10-13)。

## 增运选型：容量优先与城市环境（2026-10-13）

增加运输量时，优先评估用更大实际兼容载量的载具替换现有小载具，再考虑追加同类小载具；适用于各运输方式，不只限于高资金方案。按目标货品的实际载量、线路周转、道路和终端兼容、采购基地、维护及完整费用比较。更大车型不可行时写明具体原因，再选加车或补配套，不能默认沿用旧型号批量采购。

城市内配送同时比较原生噪音和污染，以及满足同一运输缺口所需的车辆数和车次。优先容量合适、车次较少且城市环境负担较低的方案，不只选最大载量；噪音和污染分开记录，不按型号名称或动力标签猜测数值。未知数据如实标注，必要时补查。替换先让新载具投运，再通过已验证入口退出并妥善停放对应旧载具，不自动售车、拆迁或撤空原有服务。现金底线、承诺资金、兼容、原生预览和实际投运验收仍须执行。

## 调查与缓存

- 默认局部调查。全图资源概览与全图地形/障碍快照分开：找源头可以读资源列表，不因一条路线自动导出全图地形。只在新增设施、接入走廊或明确障碍需要时补采相关区域。
- 路线初稿不要求机场、仓库和接路的精确坐标；需要施工级方案时再同步细化设施与接路，保留占地、碰撞、环境、扩建和实际连接检查。建筑小幅高差仍按 advisory 处理。
- 同一轮采用一个客户端和已绑定会话，复用读到的数据，不为每小批重新绑定并重复获取地图与账户。仍检查通道状态；会话变化、手动改动、相关实体/地形改变或准备提交时刷新受影响数据。不跨会话复用实体编号、原生预览或令牌。
- 粗略路程足以说明方案时不计算逐段速度、往返时间、发车间隔和逐平台占用。库存调查仅确认所需货品的覆盖/中转关系，不扩展为全站容量统计或服务数量验收。公共接口附带返回的数量可保存，但不继续追查。

## 详细分析与交付

普通方案一份路线说明即可；简图有助理解时再生成。无需创建全图执行包、运行 `plan_pipeline.py` 或 `plan_finalize.py`；没有地图图表产物也不为展示卡片追加调查。若生成规划图表，仍仅在最终阶段导出一次。

完整执行包继续使用 `plan_finalize.py --pack <目录>` 和 `--check` 做离线一致性检查。运营分析默认 `basic`，保留维护候选与已知终端分配，不计算详细预测。仅在用户要求时使用 `--operations-analysis detailed`，该选择写入计划的 `operationsAnalysis` 字段；专项结束后用 `--operations-analysis basic` 切回。详细分析中的未知班次或占用只标未知，不触发容量复核；有明确超限依据时才提示优化。已有输入预测保留，不在基础模式中使用或展示为本轮结果。

## 执行边界

本规则不扩大施工、购车、融资、调速或监控权限。当前目标有效性、施工原生预览、单次提交、不重发未知结果、pending 保护和结果读回保留。只规划可以记录尚待预览的候选，不能称为可直接施工。

所有载具只验实际驶离基地、正常执行所配线路且无原生故障；不额外安排返程、回库、完整往返、上下客或交付数量验证。设施本身的实际接路、必要库存覆盖与维护能力仍须按执行阶段核对。
