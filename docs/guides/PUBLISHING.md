# 模组发布流程

## 版本同步规则

每次模组升级必须同时更新以下字段，不得只更新其中一项：

- `mod/tf3_mcp_bridge/mod.json` 的 `revision`：整数修订号，每次升级递增。
- `content/tf3_mcp_bridge/bridge.script.lua` 的 `BRIDGE_VERSION`：桥接版本字符串，每次升级提高版本号。
- `_metadata/modinfo.json` 的介绍版本文字和更新说明标题：使用本次桥接版本号，与 `BRIDGE_VERSION` 完全一致。

修订号和桥接版本号同时更新，但不要求数值相同。目前基线为 `revision: 3`、`BRIDGE_VERSION = "0.12.20"`。下次升级修订号应为 `4`；桥接版本号按本次升级确定，例如补丁升级为 `0.12.21`，用户另行指定时以指定值为准。

源码与游戏本地 `staging_area/tnj_tf3_ai_bridge/` 发布副本必须同步上述字段。更新说明按桥接版本号组织，例如 `更新内容 / Changelog — v0.12.21`，不以日期作版本标题。保留中英文说明，简洁描述修复的问题或新增功能，不在模组介绍中展开实现细节或列出未验证问题；验证证据和限制另记开发文档。

## 游戏内上传

按当前用户要求，从游戏的 **Mod Hub → My Mods** 校验并上传本地发布副本，不生成 ZIP，不以 ZIP 上传作为默认流程。除非用户另有要求，不调用生成 ZIP 的 `scripts/build_mod_package.py`。

发布前核对：

1. 源码与本地发布副本的修订号、桥接版本、介绍版本及更新标题一致，且相对上一版同时递增。
2. 本地发布副本中的正式 userdata 接收器保持启用；开发源码仍可能保留供诊断工具配置的关闭初始值，不直接用整份开发脚本覆盖已启用的接收器。同步功能代码时保留或显式配置发布接收器设置。
3. 发布副本不包含测试探针、请求文件、存档、日志或个人 MCP 配置。
4. 对本地发布目录运行 `scripts/check_mod_package.py "<本地发布目录>" --require-receiver`，代码有修改时完成相应编译及功能检查，再进行游戏原生校验。
5. 上传完成后记录实际上传的修订号和桥接版本。仅修改本地文件不报告为已经发布。

旧发布产物、账本及验证记录保留历史版本信息，不为了统一当前版本而改写历史证据。
