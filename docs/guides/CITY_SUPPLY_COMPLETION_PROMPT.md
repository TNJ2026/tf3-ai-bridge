# 主城供给持续执行提示词

用于用户明确启动的 Transport Fever 3 主城供给专项。以下文本可整体复制；仅阅读、复制或修改文档，不启动游戏操作，也不恢复暂停的监控。

```text
你负责当前主城的供给专项：读取真实需求，完成必要规划与建设，持续执行到本次全部城市供给目标和前期已接机遇完成。不要只交付方案，也不要因单条线路投运而结束整个专项。

执行主线：
确认主城与需求 → 统筹资金 → 建成并验收总部 → 完成城市公交规划 → 接取可完成机遇 → 推进供给与履约 → 分别验收 → 合并交付。
总部施工前可以只读调查机遇和估算费用，但不能提前接取。具体规则如下。

一、适用范围与目标锁定

1. 开始前读取 AGENTS.md，以及 docs/guides/ 下的 AGENT_PLAYBOOK.md、ROUTE_PLANNING.md、OPERATION_COORDINATION.md、CARRIER_ACCEPTANCE.md；涉及具体设施时再读对应指南。用户最新指令及当前有效授权优先，不沿用已被覆盖的旧策略。
2. 核对连接、会话、地图、玩家、游戏时间、账户余额和接口 pending。主城以用户最新指定及当前有效任务记录为准；无法确定时先澄清，不擅自选城、换城或复用旧地图实体。
3. 读取主城原生供给需求，按真实货品 ID 去重并保存目标清单及统计基线。只有两项需求就完成两项；多于两项就处理全部实际需求，不任意挑两项。居民、商业、工业分类数不是货品数，上游原料不自动成为城市末端目标。
4. 本次目标清单锁定后，新出现需求记为后续事项，不无限扩大任务；用户明确调整时再更新。已有数量或满足率目标继续沿用；没有数量目标时按第七节的实际供货口径验收。
5. 本文不自动创建后台服务、定时任务或恢复暂停监控，不重启旧地图的初始阶段。只授权规划的任务只交付方案；已授权实施的步骤直接推进，不反复询问是否继续。

二、启动阶段：必须按顺序完成

2.1 先建设总部
- 查询当前玩家总部。已有有效总部时，核实当前实体、实际状态及必要接路后复用，不重复建设或擅自迁移。
- 没有有效总部时，为本次主城选址，按第三节资金规则和第六节施工流程建成、独立读回并验收必要接路。
- 总部已建成且验收完成，才进入公交规划；选址、报价或提交回执不算完成。

2.2 再规划城市公交路线
- 根据当前居民出行与主要目的地分布，形成可实施方案，明确线路走向、站点与站序、覆盖范围、连续通达、采购车库、维护、兼容车型及完整费用。
- 复用合理既有公交，补齐必要规划；公交换乘点与城市货运卸货站按第五节分开设置。
- 保存方案及费用依据后，才进入机遇接取。此步骤要求完成规划，不额外要求公交全部建成、购车或客流达标；公交实施按有效授权和整体建设安排推进。

2.3 然后接取机遇
- 刷新当前 UID、可接取状态及期限，按第四节接取、实施和履约。
- 不得为抢机遇跳过总部建设或公交规划；前置步骤有真实阻碍时按第八节处理。
- 保存三个步骤的完成证据和续作点。中断后只补未完成步骤，不重建总部、不重复接取已发送的机遇。

三、资金与融资：统筹完整工程

1. 初始资金方案必须同时计入总部、城市公交、主城供给和可完成机遇的完整实施费用，以及运营与偿债准备金、150万元现金底线和已有项目预留。
2. 总部施工前允许对公交、机遇作有依据的粗估和只读调查，并在已有融资授权内准备资金；公交正式规划仍在总部建成后完成。接取及付费提交前，更新相关费用、余额和承诺资金，不能重复占用同一笔钱。
3. 可使用本次明确允许的贷款额度和次数；实际借款须有有效原生报价。不突破贷款上限，不重置已用次数；已有“不新增贷款”约束时继续遵守。不能先用尽首次贷款预算再遗漏机遇工程。
4. 每次付费提交前读取当前余额及本次有效价格。支付本次费用并保留其他未完工程的有效资金承诺后，可用现金必须严格高于150万元；同时遵守当前有效预算及已消费额度。
5. 未到账预付款、未来收入和未取得奖励不能充当当前支付资金。预付款可标为条件资金，接取后确认到账才可使用；总部不能依赖提前接取机遇来取得资金。失败扣款、退款责任及偿债压力纳入风险记录。
6. 资金不足、价格未知或融资权限不明时，指出具体缺口，停止相关付费提交并按第八节处理。不侵占预留、越权借款、重置预算或无限等待资金，也不把融资缺口冒称技术上无法完成。
7. 建设及购车范围以本次有效授权为准。未经授权不拆迁、售车、抢占其他服务车辆、新建生产工厂或修改城市需求；已有专项授权的工程按其范围执行。机遇所需道路及桥隧按第四节执行，其他特殊工程按各自授权执行。

四、前期机遇：可完成的必须接取

4.1 调查范围与时机
- “前期”包括启动调查、初始融资规划及首批供给网络建设。
- 使用 get_subventions(assess=false) 获取当前原生 UID、目标、可接取状态、期限、预付款、完成奖励及失败代价；缺少关键资料时只补查相关项。
- 在初始融资定案前、每个前期独立工程收尾后各做一次有界刷新；仅评估新 UID 或实质变化项，不启动高频全图扫描或后台自动接取。
- 总部及公交规划完成前，只调查和估算；完成后才提交接取。

4.2 必须接取与允许跳过
- 候选覆盖当前地图全部城市和产业，不限主城、周边、初建范围或是否直接服务主城。跨城机遇不改变主城绑定和城市供给目标。
- 当前可接取且可完成的机遇必须自动接取、实施，不能只列建议、因偏好其他工程放弃或反复申请已授权的步骤。
- 只有具体依据证明在期限、货源、技术能力、有效授权及可用融资条件内无法完成时，才允许跳过，并保存 UID 和原因。已过期或原生不可接取的目标不提交。
- 尚未贷款、暂未购车、需要建设、目标不是城市末端需求、尚未调查，均不能单独作为跳过理由；可由已授权融资补足的暂时现金缺口也不能直接判为不可完成。

4.3 有限可行性判断
- 核算完整最小可运营方案：必要原料、道路与接路、设施、维护、载具、施工与运输时间。
- 统筹多个合同的资金、车辆和期限，不能给不同合同重复承诺同一笔钱或同一辆车。有依据的粗估即可，不要求穷举全图或积累多个统计周期。
- 机遇履约允许新建所需道路，不设城市归属、新路范围或道路类型白名单；可采用城市道路、乡村公路、高速及必要道路桥梁、隧道，无需另行申请这些建造类型。
- 道路仍按真实通达、地形、运量、时间收益和完整费用选型，保留接口能力、原生预览及验收保护，不自动授权无关工程或拆迁。

4.4 接取与履约
- 遵守第二节启动顺序后，用户明确指定的机遇按当前可接取 UID 直接单次调用 accept_subvention，不先做历史对账、无关线路评估或再次确认；目标有歧义或不可接取时如实说明，不擅自换接。
- 自动发现的候选完成上述有限判断后直接接取。逐项提交、逐项读回；pending 未结束不叠加写入，同一 UID 结果未知时不重发。
- 已接机遇持续推进到原生履约确认；期限或现场变化时刷新相关判断，不重放历史请求。合同完成标准见第七节。

五、规划规则：先形成完整可运营方案

5.1 供应链与调查范围
- 对每项货品核对源头、必需原料、生产、运输、中转、末端配送和城市接收。上游断料先补原料，末端缺运力再增配，避免只增加最后一段车辆。
- 复用适合方案的设施和允许调配的闲置车辆；找到首个有依据的合理完整方案后推进，不默认全图勘探、多运输方式穷举或精算所有班次。
- 增运选型及其他具体要求按当前 ROUTE_PLANNING.md 执行。

5.2 道路：优先考虑新路改善运输
- 规划货运、原料接驳或城际公交时，优先评估新建直达道路、捷径及必要接路，再与沿用现有路网作必要比较；不必等旧路不可用才考虑新建。
- 同步核对两端真实接入口、道路用途与规模、地形与碰撞、维护、完整费用和运输收益。改善有依据且预算可承担时优先采用；不可行、超预算或收益不足时使用现有道路并记录原因。
- 此优先级覆盖旧指南的默认复用道路偏好，但不等于无条件新建或自动拆迁。已有路线实施授权时，必要新路一并施工验收。
- 城际公交仍在本次有效客运范围内；跨城工人或旅客机遇按第四节执行，不因此扩大其他客运工程的服务城市。

5.3 接路：确认完整通达后再购车
- 公路产业运输须核对“产业内部终端 → 厂区道路 → 真实外部接口 → 本线路道路”的连续通达，以及采购车库出口能否进入运输走廊。
- 局部路口检查、设施贴路、终端支持车型，均不能代替全链通达。孤立道路或接驳缺口先纳入完整方案，接通并独立读回后再购车分配。
- 用户手动接路后刷新相关实体及预览，不重复施工或购车；未读回时标记“用户已修复，原生通达待复核”。
- 按 ROUTE_PLANNING.md 的产业道路接入前置检查执行；实际运行验收另见第七节。

5.4 城市卸货：独立设置，优先边缘
- 城市配送卸货站必须独立，不与公交换乘点共用站点设施、停靠点或终端。不同线路、名称或服务时段不算客货分离。
- 公交与货运方案分别标明设施、终端和接入口。卸货站尽量位于对应货品实际供应区域边缘，禁止设置在城市中间道路上。
- 根据需求建筑及原生配送覆盖/接收关系选址，保留货车进出、转弯和排队空间。单站覆盖不足时，规划多个独立边缘站或必要外围接路，不牺牲真实覆盖或回退到客货共站。
- 复用也须检查本约束。既有不合规站点在有效授权内先建成并验收替代站，再调整货运线路，保留公交服务；不因文档更新自动拆迁或停运。

5.5 水运资源接驳：优先一终点一线
- 码头到渔船、沙场、油井，优先每个实际资源终点一条独立线路，尽量不共线或串站；各线分别规划兼容载具、装卸和运力，不挪空其他资源线。
- 独立线路不自动要求每线新建码头；配套根据实际兼容、通达和拥堵决定。
- 独立方案受水路、终端、接口或资金等具体条件制约时，才考虑共线并记录原因。既有共线服务在获授权优化时评估拆分，不直接停运或重建。
- 具体按 docs/strategy/TRANSPORT_WATER_SITING.md 执行。

六、施工与持续推进

1. 一次只推进一个施工工程。取得公共施工锁，确认当前目标、会话及 pending；核对完整费用和资金，保存并验证必要施工前备份。
2. 按依赖顺序取得当前有效原生预览，单次提交并独立读回。接口不支持、碰撞未知或预览不完整时，不强行提交。
3. 完成道路、站点、仓库和运输维护设施后，核对实际接路、必要共库及维护能力。库存按真实 ID 去重；仓库不自动向城市或工厂配送。
4. 正确配置线路、站序及旅客上下车或货品装卸；核实车型与货品、终端及采购基地兼容，再购买或复用允许调配的载具、分配线路并读回。
5. 按第七节完成载具投运验收后，继续处理尚未完成的供货或合同目标；不得把自己的后续步骤未完成当成结束理由。
6. 发现明确瓶颈就定向处理。按当前任务有效策略考虑在途和统计延迟，不因一次空车或同一未决操作重复采购；有用户明确的增供触发规则时，以该规则为准。
7. 正常运输等待期间可以推进另一独立缺口，但不并发施工或叠加未决写请求。已完成目标保存证据后停止无依据追加，继续未完成目标。

接口额度不足时：
- 按 docs/reference/OPERATION_QUOTA.md 自动重置，无需逐次申请。
- 先取得公共锁，核对当前会话、主机、原生无 pending、相关已发送请求已终结及新鲜额度轮次/计数；单次调用 reset_operation_quota，并独立读回。
- 成功后重新获取预览，从实际续作点继续；失败或结果未知按第八节处理。
- 只重置接口操作计数，不扩大预算、贷款次数、保存额度或历史 ID 存储上限，不恢复暂停任务，也不用于清除未决请求。

七、验收：分别记录三种结果

7.1 载具投运完成
同时确认实际驶离基地（出库、出坞或起飞）、正常执行所配线路、没有原生线路或寻路故障。
满足后立即结束该载具投运观察；不要求完整往返、回库、返航、上下客或交付数量。静态配置成功或仅 noPath=false 不能代替实际出发。

7.2 城市公交开始载客
- 确认公交线路没有问题。
- 公交车都正在运行。
- 有乘客上车。

7.2 城市供货完成
- 供应链必要环节已打通、运输正常，并有城市实际收到对应货品的原生证据。
- 证据可为统计期间明确、可与本次基线比较的城市交付/消费记录，或可确认属于该城市需求建筑的实际收货记录。
- 当前已有有效证据可复用，不为取得“本次新增交付”重复建设。旧记录、窗口不清或未更新的数据不能证明当前供货。
- 用户已有数量或满足率目标时逐项达标，不以首次交付代替50%等目标；没有数量目标时不自行升级为50%或100%。
- 比例优先采用语义明确、期间可比的原生满足率；年度消费/年度需求仅作代理比率，不混用统计期间。未知不当作零或达标。
- 载货、路过城市、仓库存货、工厂产出、配置或出库成功均不能代替城市实际收货。

7.3 机遇合同完成
仅以该 UID 的原生合同状态/进度确认履约；建线、投运、载货和城市消费均不能代替合同完成。
结束整个专项前，必须确认本次全部城市供给目标，以及前期已接取机遇均按上述各自标准完成。

八、异常与通知

1. 正常调查、报价、建设、购车、投运、运输等待和额度重置只记录本地，不主动作阶段汇报，不因单项完成要求用户回复“继续”。平台强制提示仍须遵守。
2. 仅在实际错误、真实执行阻碍或全部目标完成时报告。错误/阻碍合并说明证据、影响、已完成项和具体待办；未变化状态不反复报告。
3. 原生错误、未知碰撞、请求超时、部分成功或结果未知时，立即停止相关提交，保留现场、原请求和续作点，通过已验证只读入口定向核对。
4. 禁止重发同一操作、并发叠加未决写入、清 pending、使用 ignoreErrors 掩盖错误，或擅自重载、回档、重启、用额度重置处理未决请求。
5. 已报告错误且能在现有权限内明确修复时，修复后继续；无法修复或必须用户处理时，保存续作点并说明恢复条件，不假装仍在后台执行。若当前任务另有“遇阻暂停、仅用户明确恢复”的规则，按该规则执行。
6. 会话变化、换图或时间回退后，旧引用、预览和统计基线失效，重新确认身份；目标不明时停止相关操作，不重放旧请求。用户要求停止时立即停止后续操作并保留现场。

九、记录与最终交付

1. 本地记录至少包含：主城及会话/地图、需求目标与基线、启动三步骤状态、完整方案与费用依据、预算及承诺资金、当前实体、操作 ID、提交及读回结果、验收证据、机遇 UID 与跳过依据、未完成项及续作点。
2. 跨轮或中断后从真实现场续作，不重放旧脚本、不重建已建对象、不重复购车或接取。未知及部分成功保持原样记录，不冒充完成。
3. 全部目标完成后只给出一次合并结果：主城、总部验收及公交规划状态、各货品完成证据与统计期间、机遇原生履约状态及跳过原因、实际建设/购车、贷款使用与预算占用、当前余额和明确限制。
4. 不把投运称作供货达标或合同完成，不把账户余额下降称作经营亏损。
```
