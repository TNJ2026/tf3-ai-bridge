# 总部建设指南

## 选址

- 优先复用已有总部。新建前确认当前玩家没有总部，重新读取城镇和道路实体。
- 选在主城中间道路末端附近的道路侧边，入口朝向该路段，并留出道路延伸空间。
- 主楼占地约48×40米，入口本地坐标为 `(0, -16.8, 0.05001)`。按朝向旋转占地，同时检查入口高差、碰撞和接路。
- 小型城市道路可从建筑中心距道路中心线约30米开始筛选；这只是候选距离，最终以原生入口连接为准。
- 扩建空间与主楼占地分别检查，预留约100×100米连续区域及入口通道，范围为估算。不要为了预留区避开道路而把主楼推远。

## 建造流程

1. **确认现场**：核对地图指纹、当前城市、已有总部及道路；使用当前实体，不复用旧编号或预览。
2. **备份**：记录原速度，施工期间暂停；保存独立施工前备份，确认文件本次写入完成。
3. **预览**：使用原生总部模板准备参数，检查位置、朝向、高程、碰撞及入口自动连接。总部PERSON端点到道路的连接图必须双向可达。
4. **单次提交**：调用 `build_headquarters(town, x, y, z, rotation)` 获取预览令牌，再由 `commit_facility(preview_token)` 消费一次。预览与提交保持同一位置和参数；严格检查错误、警告及碰撞，不绕过原生检查。
5. **独立验收**：重新解析已建总部，核对位置、朝向、归属和主楼模块；读取真实 `TP_NET_LINK` 与PERSON车道，验证入口到道路双向连接。
6. **保存**：更新该地图固定自动存档，确认文件已写入。正常完成后恢复施工前速度；出现未知结果即停下核对现场，不自动重发。

只规划时止于候选和预览，不提交建造。已建总部标记 `reuseOnly`；找不到原位设施时重新调查，不自动补建。用户明确删除并要求再建时，创建新的任务和回执，从上述流程重新开始。


## 按需通道的有界验收（2026-10-10）

新通道可先调用 `preview_headquarters_access(town,road,x,y,z,rotation?)` 获取一次原生提案的PERSON连接图；建后及重载后调用 `get_facility_access(entity,person_graph=true)`，将返回的 `personGraph` 交给 `scripts/hq_access_probe.py` 的 `analyze(graph,existing_entities=graph["hqEntities"])` 作双向检查。后者读取全部总部子设施中的交通网络，包含未连接的子网络；不生成提案、不执行原生寻路。响应有界，超限或缺失返回未知，不能宣称连通。

当前v12已在2222测试图完成总部新建、实际主楼/归属/位置读回、保存重载及建后四个PERSON节点到城市道路双向图验收。它证明该现场连接图，不证明任意地图长期模拟安全。不要用完整 `get_entity(HQ)` 获取大型总部组件：本次达67,671字节，超过64KB响应上限；配置用 `get_facility_layout` 的有界页面。

使用按需通道时，不直接运行下面依赖旧文件通道并包含多次原生寻路的历史脚本。历史命令仅用于理解其算法；当前按需通道使用上述两个有界接口。

## 脚本入口

方案需包含当前地图指纹、主城、唯一HQ候选、明确的地面高度，以及目标道路的调查数据。每次使用新的输出路径。

离线准备：

```powershell
server/.venv/Scripts/python.exe scripts/plan_hq_access.py --plan <方案.json> --output <结果.json> --prepare-only
```

用户明确要求当前城市原生预览时，将 `--prepare-only` 改为 `--current-map-test`；脚本核对镜头城市、地图指纹和暂停状态，并保存备份。加载隔离测试存档时使用 `--isolated-test-save`。两种模式均只预览，不建造。

已建总部只读验收：

```powershell
server/.venv/Scripts/python.exe scripts/hq_existing_access.py --plan <方案.json> --output <新验收结果.json>
```

脚本重新解析当前玩家唯一总部，读取实际车道和自动连接，不生成建造提案。建造由标准 `build_headquarters` → `commit_facility` 接口完成，不直接重放任务目录中的一次性建造脚本。

## 结果判定

- `built`：建造回调成功；`verified`：位置与配置读回匹配。
- `access.entranceConnected`：根据真实车道及自动连接计算的入口双向连通结果。设施 `attachments` 为空不能单独判定未接路。
- `nativePathQueryPassed`：原生点到点查询结果，单独记录。该查询对自动连接的覆盖尚未确认，不单凭空结果判定入口断开。
- `constructionReady` 与 `operationalAccepted` 不由单次入口检查自动放行；升级范围、运行及重载按各自验收范围记录。
