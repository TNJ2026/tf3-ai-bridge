# 可配置航空集合

集合占地可通过设施间距、道路长度和模块组合调整，建筑本体不做几何缩放。入口为 `scripts/configure_hub_template.py`，只读取本地模板并生成候选，不连接游戏，不施工，也不替换默认模板登记。

## 配置与生成

```powershell
server/.venv/Scripts/python.exe scripts/configure_hub_template.py --template exports/hub_template_displayed/template/hub_template.json --config config/hub_compact.json --output exports/hub_configurable_compact
```

输出包含 `hub_template.json`、联合预览输入 `joint_spec.json` 和示意图 `layout.svg`。示意图不是精确占地、地形或覆盖验收图。输出目录必须与输入文件分离。

| 字段 | 含义与限制 |
| --- | --- |
| `name` | 候选名称 |
| `offsets` | 按 `bus`、`truck`、`warehouse` 指定局部 `x/y` 位移，单位米；直升机场为固定锚点，整体平移和旋转留给放置阶段 |
| `moduleSlots` | 按角色列出保留的已记录槽位字符串；省略角色则保留全部，不能凭空添加槽位 |
| `frontExtension` | 前沿道路左端延长量，正值延长，负值缩短 |
| `outerExtension` | 前沿道路右端延长量，正值延长，负值缩短 |

移动客货站时，道路端点随相邻站点移动，中间节点按两站位移插值，共享节点使用一致的平面切线方向。当前仅支持沿局部 X 单调排列的一条道路链、客货站各一个入口，不支持分叉、任意单体旋转或自动贴合地形。站点次序反转或道路节点间 X 间隔小于 2 米时拒绝生成；这只是几何检查，不代表原生最小路长或转弯半径已通过。

## 两个示例

- `config/hub_compact.json`：货站和仓库沿局部 X 各移动 -20 米，外端道路缩短 20 米，保留原有全部模块。它是紧凑候选，尚未验证建筑之间是否碰撞或仓库是否仍在覆盖内。
- `config/hub_reduced_modules.example.json`：客车站保留两个平台及入口，仓库保留三个通用模块，移除直升机场附加降落平台，货站保持不变。移除仓库模块会改变容量与货物适用性，必须根据实际配送货品重新核对。

模块选择强制保留车站所有已记录的出入口及至少一个平台，仓库至少保留一个模块。直升机场扩展列表可为空，但基础建筑是否接受该配置仍须原生预览。已有槽位子集也不保证模块之间依赖有效；新增平台、仓储模块或更大规格必须先获取原生扩展设计，不能简单修改数量。

## 接入与验收边界

生成时清除原模板的覆盖与道路连通结论，并标记 `requiresNativePortRefresh=true`、`nativeJointPreviewPassed=false`、`constructionAuthorized=false`。源实体仅用于追溯，不能代表新配置。

这些输出目前接入实验性联合提案编译器，详见 [联合提案原型](JOINT_HUB_PROTOTYPE.md)。生成文件不等于已经完成联合原生预览或一键施工。旧 `build_displayed_collection.py` 逐项施工入口依赖原现场建筑复制与模块比对，尚未接入这些模块变体，不要修改默认登记后直接调用旧入口施工。

后续原生预览须重新生成并解析入口几何，尤其原模板客车站入口曾手动延长，不能直接沿用源道路端口。模块变化、设施位移、道路变化之后，重新检查旋转占地、升级空间、坡度、碰撞、共同仓库覆盖、储存货品、双向车辆和步行路径；仍按当前会话重新解析、预览、单次提交、读回验收。
