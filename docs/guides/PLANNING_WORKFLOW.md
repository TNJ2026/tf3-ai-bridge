# 全图规划准备与耗时优化

新地图候选生成入口为 `scripts/plan_pipeline.py`：输入快照、需求明细与产能，一次完成模板布局、供给网络、执行清单、统一预检和分类索引。已有完整方案继续使用 `scripts/fullmap_workflow.py` 预检。两者全程离线，不连接游戏，不显示卡片，不以旧地图目录或历史编号代替当前输入。

## 先获取平整区域，再选择集合（2026-10-04）

1. `capture_planning_snapshot` 默认在同一次地图读取之后、本地分析采样地形，返回 `flat_areas_path`、区域摘要和精查提示；不增加游戏查询，不显示中间卡片。可用 `include_flat_areas=false` 关闭派生分析。全图粗采样间距按地图大小和10万个点上限选择，通常100～250米；粗采样只用于找到方向。
2. 离线流水线先运行 `plan_flat_areas.py`，输出 `flat_areas.json` 与透明的 `flat_areas.svg` 图层，再生成集合布局。区域按干燥、平缓网格单元四邻接合并，保存精确的逐行单元范围；区域包围框内可能有水域或陡坡孔洞，不能把整个框当成可建空地。此阶段不排除建筑，也不证明覆盖或接路。
3. 集合候选仍在原有有界道路锚点、朝向和外接长度内生成，但先比较**整组旋转占地、组内道路及估算扩建范围**的地形，再核对障碍、城市退距、道路连通分量及接路。先选整组和接路都平缓的候选，然后按最大采样地表坡度、高差和距离排序，避免遇到第一个可放建筑的位置就定址。
4. 默认5%地表坡度、集合5米采样高差仅为规划优先项，20米扩建边带也是估算，均不是原生施工或升级安全阈值。没有平整候选通过全部检查时，保留较缓坡方案并记录 `terrain_screen.fallbackReason`；仍不自动施工。`terrain_screen` 同时保存地形指标、调查范围、采样间距及候选检查数量。
5. 对优选集合和接入走廊补采局部25米地形；更小的端口高差还须原生检查。间距大于25米的方案在 `review_queue.json.localTerrainSurveys` 中列出局部调查范围，`pipeline.json.requiresAttention=true`。此离线入口不自动连接游戏精查，不把插值当新测量。局部新快照需重新做布局检查，实际固定道路端口必须重新解析和预览。

`flat_areas.json` 保存地形网格摘要和策略版本；布局缓存包含地形策略，流水线缓存还包括分析代码。换地形或算法后不复用旧选址。单独执行 `plan_template_map.py` 时也先生成或核对平整区域文件；旧文件与当前网格不一致则拒绝使用。

城市与陆上生产点中心距离小于 3000 米时，先按[共用集合规则](GROUPED_CONSTRUCTION_WORKFLOW.md#无限资金模式的默认集合选址)评估共享：城市定址 → 道路效率筛选 → `shared_industry_hubs` 映射 → 未共用生产点定址。网络生成解析映射，合并同向货流并避免同集合航空自环；共用容量和工厂真实道路出入口仍需验收。缓存包含共用规则版本；既有施工方案、建筑和日志不自动迁移或拆除。

## 2026-10-04：避免边规划边拼脚本

1. 在首次游戏调查前启动 `planning_clock.py start`，完成最终交付后 `finish`。阶段脚本耗时自动写入 `pipeline.json`，与整轮墙钟分开统计。勘探期间继续设计时，不开启排除计时；只有完全停工等待勘探时才使用 `wait-start/wait-end`。
2. 首次生成前校验快照、需求、产能的产业编号/类型/位置，以及模板角色。生产模板缺少第二坪立即报错。对捕获的城市车库/货站共享入口模板，自动应用已验证的20m后退方案并生成短接路；不修改原始捕获模板，不把这一修正当作新地形的原生验收。
3. 生产端只在生产设施所属道路连通分量中找锚点，排除冻结节点；有限候选仍找不到就报告局部设计问题，不能跳到另一片路网。相同水域优先共用一个船坞候选，岸线和航路仍需原生检查。
4. 先检查代表性城市/生产集合与岸线，再批量展开；联合建筑预览失败后，才对该集合逐建筑诊断。不要全图重复跑单体预览，最后才发现入口冲突。`review_queue.json` 保存检查顺序、对象和最多三个候选的预算，只是队列，不自动执行原生调用或放行施工。
5. `--baseline` 复用离线布局/网络；缓存同时校验输入、模板、算法代码及输出摘要。产能变化只重算网络，几何/快照变化使布局缓存失效。`--redesign <owner实体编号>` 在同一输入下只重选指定集合，供给网络及全图空间/依赖预检仍重算。复用时清除原生结果和令牌。
6. 局部原生检查用 `plan_native_preview.py --owners T<城市ID>,I<产业ID>` 或 `--ids <规划对象ID>`。集合相关设施、接路及城市停靠点可分别按 section 批量检查；未知编号立即失败。范围筛选不证明其他对象仍然有效，正式提交前仍须重新读取当前世界。
7. 直接交付流水线生成的分类索引；只有必要的复杂岸线、原生失败或供需解释另补专题，避免重复手写整套报表。`plan_refine_sites.py`、`plan_finish_delivery.py`、`plan_write_report.py` 含本次怀化专用修正或统计，不能作为新地图通用入口。

```powershell
# 开始整轮计时，不连接游戏
server/.venv/Scripts/python.exe scripts/planning_clock.py start --file <本次计时.json>
# 先取得当前地图的三份输入；输出目录必须为空
server/.venv/Scripts/python.exe scripts/plan_pipeline.py --snapshot <当前快照.json> --details <需求明细.json> --capacity <产能.json> --output <新目录>
# 相同几何下，仅重选指定产业集合；更换输出目录保留历史证据
server/.venv/Scripts/python.exe scripts/plan_pipeline.py --snapshot <当前快照.json> --details <需求明细.json> --capacity <产能.json> --output <修订目录> --baseline <上次目录> --redesign <产业ID>
# 需要实时检查时才调用：只读，但会连接游戏；先确认当前会话
server/.venv/Scripts/python.exe scripts/plan_native_preview.py --plan <方案.json> --output <结果.json> --section groups --owners I<产业ID>
server/.venv/Scripts/python.exe scripts/planning_clock.py finish --file <本次计时.json>
```

离线回放（怀化已保存快照；未连接游戏）：首次生成1.36秒，相同输入复用0.69秒；单集合重选1.23秒，其余27集合保持不变；仅产能变化1.09秒且复用布局。10条车库短接路自动生成，三个渔场共用一处船坞候选。7项新增回归测试及60项原有全图测试通过。记录位于 `exports/planning_optimization_replay_20261004/`。

这些是候选准备时间，不是把36分钟完整规划降到了1秒。新地形的原生岸线校验、真实入口绑定、覆盖和运营检查尚不能省略；本次优化没有连接游戏，也没有新增原生安全证明。离线结果仍可能 `requiresAttention=true`，必须按问题与原生证据逐项处理。

## 固定顺序

1. 采集当前会话的输入，先查看同一快照派生的平整区域，再确定集合候选和局部精查范围；资源勘探完成后重新获取快照。勘探等待单独记录，不计规划耗时。
2. 初选就联合检查设施、升级空间和道路。`search_sites` 可传入 `access.anchor`（当前道路候选锚点）、`access.local_entry`（设施局部入口偏移）和 `access.max_grade`（默认0.10）。按候选朝向旋转入口，在排序前剔除跨水、快照越界和明显陡坡的直连接路。这只是粗筛；弯道、桥梁和真实端口须另行设计，不能把粗筛当原生可建。
3. 新设施编号使用 `fullmap_identity.facility_id(owner, role, context)`，例如同一渔场分别采用 `shore` 和 `air` 上下文。不要自动给重复旧编号加后缀，因为已有引用可能指向另一个对象。执行器在原生查询前拒绝重复编号。
4. 完成初稿后运行统一预检，再处理报告中的问题。编号、引用、任务覆盖、清单姿态/参数、依赖循环在耗时筛选之前校验；旋转后的当前占地及升级预留每轮重新计算，不信任移动前遗留多边形。
5. 原生预览保持每批8项和有限候选预算。局部修改后重跑离线入口，并根据依赖变化及空间冲突复核受影响项目。所有正式提交仍要求新会话核验、实体解析和原生预览；不可复用旧令牌。
6. 一次生成分类汇总、坐标CSV、执行顺序、问题列表和独立阶段计时，最后只导出一次地图卡片。统一报告是预检交付，不自动替代供需分析、设施尺寸依据和完整线路论证。

## 命令

```powershell
server/.venv/Scripts/python.exe scripts/fullmap_workflow.py --plan <方案.json> --snapshot <快照.json> --manifest <执行清单.json> --output <独立输出目录>
# 局部修订后，使用上次输出作为离线缓存基线；输出到新的目录。
server/.venv/Scripts/python.exe scripts/fullmap_workflow.py --plan <修订方案.json> --snapshot <同一快照.json> --manifest <同步修订清单.json> --baseline <上次输出/preflight.json> --output <新输出目录>
```

输入与输出目录必须分离。失败写入 `failure.json` 并返回非零，不继续后续阶段。正常产生 `preflight.json` 也不意味着可直接建造：必须阅读 `requires_attention` 和 `ISSUES.md`。

## 缓存与局部重算边界

- 道路候选缓存只用于同一完整快照摘要、相同算法版本及相同道路参数。换快照、改道路或算法升级即失效。它不缓存实体查询、原生预览或施工结果。
- 道路粗筛只针对快照地形及障碍；规划设施的旋转占地、扩建空间每轮全量复核，不把未变化任务视为空间安全。
- 清单变化通过依赖关系传递到线路、车辆与运行验收；移除项目单独列出。局部重算列表仅用于离线工作调度，不能缩减建造前的当前游戏检查。
- 清单缺少产业指纹时报告阻塞项，不从“城市相同”推断整张地图相同。新清单须在 `session.industries` 中保存资源名和坐标。四处码头若只有位置没有尺寸，同样报告缺少几何，不默认为无冲突。

## 本次离线验证

咸阳快照回放：138处建筑、78条道路、521项任务。首轮预检及分类交付约0.8秒；相同输入回放78条道路全部命中离线缓存，约0.7秒。两次都重新计算设施几何。

粗筛报告保留4处既有扩建限制、旧清单缺少产业指纹、4处码头缺少占地尺寸，以及需要局部接路设计的道路。粗筛会保守拒绝交叉口或陡坡；拒绝不等于原生引擎认定不可建，必须另行设计并核验。

此数据只证明准备与交付步骤已整合，不能将上次22.4分钟整体规划宣称降至1秒。供需初稿生成、复杂岸线调整和完整原生校核还未成为一个无需干预的全自动流程。下一次实际规划仍需测量包括分析与修正的总墙钟时间。
