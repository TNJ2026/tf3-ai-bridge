# 船舶航路故障诊断（非投运门槛）

## 显式诊断范围

以码头为中心，只检查计划实际使用的航段：

- 船坞 → 码头，以及码头 → 船坞。
- 码头 → 每个服务渔场，以及各渔场 → 码头。

不检查渔场之间、船坞与渔场之间没有运输任务的路径。同一船型配置、同一码头终端、两个渔场时，共3对航段、6次方向查询。不同终端、通行模式或配置会增加必要检查。

常规投运仅检查实际出坞、正常执行线路、无原生故障；不得把以下诊断算法作为必经步骤。

## 去重与缓存

离线按线路实际端点、终端索引、通行模式和船型配置合并重复航段，保留关联线路编号。原生读取时按实际起终点节点、方向、通行模式和配置缓存；去程与回程分别检查。不可达结果可以在当前批次复用，异常立即停止。

缓存只存在于一次引擎查询中，不写入可复用文件。下一批次、重载及设施或岸线变更后重新解析端点；不能把上次结果作为当前通航证据。默认按具体船型区分；不同船型只有明确指定等效 `navigation_profile` 后才能共用，船型附加限制仍单独验收。

## 入口

从最新方案生成精简航段清单，不连接游戏：

```powershell
server/.venv/Scripts/python.exe scripts/ship_route_checks.py --plan <方案.json> --output <新清单.json>
```

仅在明确要求航路故障诊断时，加上 `--readback --diagnose-round-trip`；可用 `--port-id <码头规划编号>` 限定单个港口。每次使用新输出路径。

脚本先核对地图指纹，再按资源和位置重新解析设施，确认计划终端及船坞进出节点。缺失、歧义、过期节点或遗漏服务渔场均不放行。`fish_port_collection.py` 常规建后验收不再调用航路往返查询；设施放置、共库和维护能力仍独立验收。

## 验收范围

规划阶段检查水域、岸线、入口方向及航道空间，清单标记 `nativeVerified=false`。建后 `verified` 只表示指定通行模式下必要航段双向可达；船型附加限制、真实装卸、维护、吞吐与长期运行单独验收，`operationalAccepted=false` 不自动改变。共库检查使用指定主仓库，与航路检查分开。
