# 账户监控与免历史对账

2026-10-13：主城监控以[七项简化提示词](MAIN_CITY_DEVELOPMENT_MONITOR_PROMPT.md)为准，下文“只读取账户”不再是完整业务范围。账户作为支出判断辅助；仅道路故障修复豁免150万元底线，其余仍保留底线及承诺资金。免历史对账、未知字段和pending保护继续适用。现有脚本能力未因文档更新而增加，本次不启动或恢复监控。

2026-10-12 用户要求取消业务对账，只监控账户余额与收入以避免欠款，并选择现金底线150万元。

- 取消逐笔报价—扣款匹配、整线车辆ID与历史账本一致、无关历史未确认记录阻塞、仅因存在执行账本而拒绝离线规划收尾。不再自动重查全部历史工程或机遇。
- 只读取当前账户余额、原生收入（含统计期间）和原生贷款余额。保留可比余额趋势，但明确它可能包含建设和还贷，不能称为收入、净利润或经营亏损。
- 当前 `get_finances` 仅公开余额、贷款余额和无限资金状态，未公开收入统计。收入保持未知；不逐车推算、不把现金差额当收入。新增收入接口须有明确原生字段依据，不能猜测调用。
- 达到或低于150万元时停止新增付费建设和购车；不停止现有线路、不自动卖车、不自动借款。持续余额下降、负余额或贷款余额增加时提示风险。未知余额不能宣称财务安全。
- 已授权工程总预算、采购上限及借款次数仍有效。报价只用于预算和支出前判断，不要求与单笔现金变动相等；历史未入账报价不触发追账。下达付费命令前仍检查本次报价和当前余额，防止一笔支出越过底线。
- 同一请求或操作ID不重发，接口尚在处理时不并发写入，不清空pending。保留本次施工原生预览、当前实体/目标有效性及结果读回。这些保护不会启动历史业务对账。已有未确认操作不得标记为已成功；跳过后应保留未完成状态。
- 地图/玩家/会话变化使趋势基线失效，不重放旧请求。显式故障恢复工具保留供诊断，正常监控不调用它。历史账本、存档和回执不删除。

实现：`OperationsMonitor.once` 仅调用 `get_game_state`、`get_map_info`、`get_finances`，由 `finance_watch.assess` 生成风险和去重通知。`monitor_city_health.py` 保留原CLI参数，改为一次账户采样；不再扫描城市、载具、库存、候车或机遇。

监控保持暂停。代码变更需要新进程加载；本次未启动定时器、未重启MCP、未连接或修改游戏。仅轮询本身不能保证账户永不欠款，已有线路费用和还贷仍会发生。
