# 三门峡全图规划与施工复盘

日期：2026-10-03。用户决定本地图暂告一段落；本复盘不授权继续施工。适用范围：Transport Fever 3 全图货运规划、批量施工与存档恢复。

## 1. 最终状态与证据

恢复原始施工前备份后，144处建筑静态核验通过；1380段道路和1372个关联节点均存在运输网络组件。36条航空/公路枢纽共享库存关系及5处码头共享库存关系通过，36条关系包含复用设施的条目，不代表36座独立枢纽。

47条计划道路连接尚未接通；另31条接入项没有原生道路端口，功能仍待判断。53组城市卸货点全部未建，16城通过计划卸货点覆盖的需求库存为0/689。当前无运营线路，尚未形成完整配送链。

崩溃前曾完成的27条道路和53组卸货点未保留在恢复后的存档中，不能沿用旧完成标记。详见[当前存档验收报告](../../exports/newmap_plan_20261003/construction/recovery_20261003_1758/ACCEPTANCE.md)及其证据链接。

## 2. 保留的有效做法

- 全图统一盘点需求、产能及原料约束，再分配生产点与城市。无限资金不消除产能缺口、路程、地形、声誉、噪声、扩张空间和吞吐限制。
- 仓库、货车站、航空和水运设施按真实共享库存与装卸能力验收，不以距离近或图上相邻代替货物流通证据。
- 道路优先直线及平滑曲线，延长道路优先沿现有末端切线；设施预留升级占地、出入口和接驳通道。
- 原始备份、提交记录和读回结果分别保留，使失败操作可追溯，恢复后可重新核对进度。

## 3. 规划与执行优化

|本次问题|后续规则|
|---|---|
|建筑先建好，接路阶段才暴露坡度、朝向和碰撞问题|设施与道路联合选址；长接路先验证地形走廊，再确定建筑位置。建筑尚未建成时标记端口预测，建成后重新解析真实外部端口并预览。|
|大量建筑落地后仍没有完整配送链|保留全图供需总方案，执行按“生产点—中转—城市”划分。先验证代表性链条，再按同类模式扩展；不同地形、端口和设施类型仍需单独验证。|
|内部冻结节点被误当道路入口|排除 CONSTRUCTION.frozenNodes；最近节点或度数为1不足以证明是外部端口。源端和目标端都要检查。|
|预览通过但提交触发引擎断言|预览是必要条件，不是安全保证。首次采用一种施工方式时先小规模验证，再扩大批量，不在正式存档试未知提案。|
|没有原生端口就归类为“不适用”|分别标明“无需独立道路且有机制证据”“已验证其他接入方式”“仍待功能判断”。没有端口不能直接计为验收通过。|
|重载后旧账本保留完成状态|历史请求记录不可覆盖；另建当前会话验收状态。按位置、资源和拓扑重新解析实体，明确已保留、已回档、待核对三类。|
|自动存档和备份名称相近|记录完整文件名、时间、大小、用途及验收阶段；明确区分原始备份与 autosave_ 同名衍生存档。|

代表性运输链验证必须遵守授权范围：仅授权基础设施时，完成接路、终端和库存覆盖验收；线路、购车及模拟运营按各自授权执行，不为“闭环验证”擅自扩大操作范围。

## 4. 崩溃经过与检查遗漏

已确认的经过：误选货站内部冻结节点接路，预览通过，提交触发 TransportNetworkSystem.cpp:635 / AreAllNodesEmpty。之后道路实体仍存在，但部分 TRANSPORT_NETWORK 数据缺失。最近一次闪退日志显示，UI::CSelector 读取入口道路87919的缺失组件，触发 Engine.h:323。

agent 的恢复检查存在遗漏：仅凭原道路实体存在、未出现新边判断失败未生效，未立即检查生成的运输网络组件，就继续其他施工。因此异常状态进入后续存档，扩大了回档损失。历史编号仅用于解释事故，不得作为新施工参数。

后续硬性规则：

1. 遇到原生断言、未知提交结果、超时或部分成功，停止整批世界修改；不能因其他地点看似正常而继续施工。
2. 先只读核对实际状态，至少检查端点、相邻道路、TRANSPORT_NETWORK、旧引用及站点拓扑。道路实体存在、新道路未出现，不足以证明回滚成功。
3. 检测到组件缺失时停止原生预览和提交；保留日志与异常证据，恢复独立备份后重新检查。
4. 不能用 Lua pcall 或 ignoreErrors 防护或绕过原生引擎断言。首次异常未完整回滚的引擎原因仍未查明，不声称彻底修复。

## 5. 批量速度与验收分层

提速优先减少重复查询和无效候选：同一会话使用地形、障碍及设施快照；本地筛选后只对少量候选作原生预览。只读调查可以合并请求，世界修改仍单次提交、明确读回。换图、重载和道路替换后失效相应缓存。

每批规模按施工类型和风险确定，避免未验证方案大批扩散。保留固定滚动自动存档槽，同时独立保留施工前基线；异常现场不能覆盖最后一个已验证检查点。覆盖存档须确认本次文件更新且写入稳定。

|验收层次|证明什么|不能替代什么|
|---|---|---|
|建筑与组件|资源、位置、归属、必需组件存在|接入、运输和长期稳定性|
|道路与终端通行|实际接点及 CAR/TRUCK 等适用模式的双向路径有效|货品装卸和城市覆盖|
|库存与末端覆盖|共享库存、终端装卸和城市需求库存可覆盖|真实供给量和生产能力|
|运营与观察|经授权运行期间的流量、排队、车辆状态和交付情况|超出观察时间的长期安全保证|

## 6. 下一张地图的执行顺序

全图需求与产能调查 → 供给分配 → 代表性链条工程验证 → 设施与道路联合选址 → 小批施工 → 组件、通行和库存覆盖验收 → 经授权运营观察 → 保存对应阶段检查点 → 扩展下一批。

可复用的是经过验证的规则和流程，不是旧地图实体编号、旧预览或未验证的脚本假设。
