## 汽车、船只及其他维护设施

### 先区分购置能力和维护能力

本地原生定义中，购车车库/船坞包含容量和出入节点；独立维护站则定义维护模式、范围和维护池。不能把仅有维护服务的设施当作购车点，也不能把覆盖圈内的一条路线当作出库可达路线。

维护选址建议优先覆盖车辆**经常经过且有足够服务机会**的位置，如装卸站、终点、几条线路共同走廊，而非地理上离所有线路平均最近的位置。具体停留时长收益、多个设施叠加和服务分配规则需运行观察，不默认线性叠加或瞬间修满。

| 设施 | 当前本地定义维护半径 | maintenancePool | 选址重点 |
|---|---:|---:|---|
| 公路购车车库 | 400米 | 12 | 优先调查城市对外连接口路侧；综合住宅噪音、城市扩张、出入库路径和实际线路维护覆盖 |
| 专用道路维护站 | 默认600米，可被参数覆盖 | 16 | 公交/货车/电车常经节点，长途线两端或维护下降明显区段 |
| 铁路购车库 | 800米 | 6 | 接轨和出库不阻塞主线，兼顾列车经常停靠位置 |
| 专用铁路维护站 | 800米 | 12 | 多条铁路服务区、站场周边；模式包括普通与电力列车 |
| 船坞 | 1000米 | 8 | 出坞可达与港区维护兼顾 |
| 专用船舶维护站 | 1400米 | 12 | 主要泊位或常用航道，模式包括 SHIP/SMALL_SHIP |
| 电车车库 | 400米 | 12 | 电车网络出入与经常停靠位置 |
| 固定翼机场/简易机场机库模块 | 550米 | 16 | 按机库实际位置覆盖停机和滑行服务区 |
| 直升机购机基地 | 800米 | 4 | 两端周转节点和已有停机坪，减少长期脱离服务 |

以上为2026-10-03安装资源的字段值，不是保证可同时修理的车辆数量，也不是单车每秒维修率；维护池、车库停放容量和站点容量不可混用。建筑旋转、模块位移会影响范围中心，不能固定以建筑图标中心测距。[原生摘录及资源哈希](../../exports/transport_siting_20261003/native_evidence.json)

### 公路车库通用选址（2026-10-10）

本节是跨地图的选址原则，不引用任何特定地图的坐标、实体或车流作为默认方案。优先复用现有车库；新址优先调查城市外围、靠近服务线路共用道路或终点、住宅较少的一侧。城市对外连接口只是优先候选，不能仅凭“城外、路边、空地”确定位置。城市扩张必须在初筛时考虑。

| 因素 | 调查与取舍 |
| --- | --- |
| 噪音 | 避开现有住宅及预计住宅扩张方向，同时核对设施自身影响和车辆出入库路径，避免货车穿过住宅街区。按实际噪音图层与资源信息核对，不编造统一安全距离。 |
| 出入库距离 | 比较车库到所服务线路首站、终点及返库的真实道路时间，计入绕行、转向和拥堵；市中心直线距离只可用于初筛排序。 |
| 维护覆盖 | 优先覆盖车辆日常必经路段、终点或装卸站，留出覆盖余量；结合维护能力和完整运营周期内车辆状态变化验收。覆盖圈擦过路线不等于维护充分。 |
| 道路接入 | 入口朝向道路，核对双向出入；避开繁忙交叉口及站场排队区，减少出库车流与运营交通冲突。 |
| 地形与扩建 | 优先平坦、入口高差小的路侧地块，为建筑扩建、进出通道及道路升级保留连续空间。 |
| 数量与成本 | 出入库过远、网络隔离或能力不足时才评估增建，不按每城或每条线路机械配一座；有限资金时比较建造与持续维护成本，无限资金也应避免无必要的环境负担。 |

距离须分开衡量：离住宅的距离看噪音影响，离线路的距离看维护覆盖，出入库距离看真实行驶时间。不套用直升机场500米退距，也不把维护半径当作噪音安全距离。污染按整个市政区域统计，移到城市边缘不能自动消除污染影响；复用和控制无必要的设施数量同样重要。[官方噪音与污染说明](https://www.transportfever3.com/news/dev-blog-episode-4-tycoon/)

城市扩张按以下三个层次记录，详见[城市发展范围预测](../guides/AGENT_PLAYBOOK.md#35-城市发展范围预测)：

1. **现有建成区**：按实际建筑外缘区分住宅、商业和工业，不能用市中心代替边界。
2. **近期扩张估算区**：结合既有道路及延伸方向、连续空地、住宅分布、地形和水域预测；记录数据时间、判断依据和不确定性，不将估算当作确定的未来建筑边界。
3. **长期预留区**：为城市新增街区、主要拓展通道、干道延伸，以及车库自身扩建和出入口分别留空间。目标人口或城市等级不明确时标为暂定情景，不设无依据的统一缓冲半径。

在接入与服务条件满足时，优先城市外围工业、物流一侧；避免把车库放在预计住宅扩张方向、城市主要拓展通道或道路未来延长线上。今天位于城边不代表未来仍在城外，不能只检查当前空地能否容纳建筑。

按用途选择位置：公交车库优先城市边缘的公交终点或多线共用走廊旁，选择远离住宅的一侧；货车车库优先工业区外缘、货运枢纽或主要生产点接入道路旁，减少穿城；客货共用车库须确认双方出入库和维护都有收益，不仅比较几何中心。

购车调度与日常维护分别评估。官方说明车库可以维护范围内车辆，独立维护设施覆盖范围更大但不能购车；不要求车辆为日常维护专门回库。[官方车库与维护说明](https://wiki.transportfever3.com/doku.php?id=gamemanual:infrastructure:stationsdepots)

如果避让住宅扩张使车库远离日常线路，应比较“外围车库＋线路附近独立维护站”，而非盲目加建完整车库。独立维护站也须检查自身噪音、污染、扩张冲突和实际维护能力；长途线路按车辆运营状态评估沿线维护，不要求一座车库覆盖全程。

方案记录至少包含服务对象、真实出入库路径、维护覆盖及能力依据、住宅与三层发展范围、扩建预留、未验证事项和选择理由。城市增长、线路调整或道路变化后复查。规则用于后续规划，不自动授权迁移、拆除或重建现有车库；候选仍须按当前会话原生预览和建后读回验收。

### 汽车/船舶的具体建议

道路维护站优先放在线路共用的外围道路或装卸枢纽附近；长途货车若从远处城市车库出发，要检查首次到达产地前及日常循环的状态，必要时在生产端补维护。徐州已出现产地货车需要就近维护的实例。独立维护范围不等于必须安排车辆回库的线路停站。

船舶维护站优先比较港区侧翼、常用航道交会处和长航线端点。可覆盖多个泊位时，仍需观察集中到港时的维护变化；不要把圈刚好擦到航道作为充分服务的证据。岸线、陆地/水面可放置规则依当前资源预览，不能套用船坞的建造规则。

### 维护验收

读取实际 `transportModes`、`maintenanceCatchment` 与 `maintenancePool`；在完整运营周期多个时点检查车辆 `maintenanceStation`、`maintenanceState` 和 `maintenanceChange`。途中离开服务区出现下降并非立即失败，关键是返回服务节点后能恢复，且多周期没有持续恶化。官方 API 中有车辆维护站及相关组件字段；具体语义以当前版本定义与观察为准。[官方引擎 API](https://wiki.transportfever3.com/script-doc/api/engine.html)
