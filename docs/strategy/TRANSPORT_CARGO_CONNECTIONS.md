# TF3 仓库、货站与客运接驳配套

更新：2026-10-03。返回[交通设施选址总览](TRANSPORT_FACILITY_SITING.md)。

适用范围、证据分级和统一施工规则见总览；以下位置取舍为规划建议，当前参数须按版本和存档核对。

## 仓库与多式联运布局

官方介绍确认 TF3 将仓储和专用装卸设施纳入货运体系。[官方货运介绍](https://www.transportfever3.com/news/first-look-episode-2-industries-and-cargo/)

本项目已运行验证的中转布局：

```text
来源库存 → 第一段车辆 → 货站A ┐
                            ├─ 同一仓库库存被A、B覆盖 ─→ 货站B → 第二段车辆 → 消费端
                            ┘
```

这是同一个库存能被两段交通访问，不代表仓库会无条件把货物自动搬到另一个远处仓库或工厂。货站、码头、机场相邻，或两站客运换乘关系存在，都不足以证明货运成立。核对 `getStationCatchables(station,true)` 的库存实体交集，再用装卸日志验证。目的地直接有可接受货物的消费库存时，应按实际需求判断是否还需要中转仓，不机械要求每个终端都额外建仓库。

仓库位置应先满足所需交通方式的共同覆盖，再争取平缓地形和连续扩建面。扩容后重新检查实际库存实体与站点覆盖，不只看旧仓库中心仍在圈内。多座仓库时注明哪座负责哪次换装，避免圈内“有仓库”却没有正确的共享库存。

容量按批量到货、发车间隔、实际生产/需求及延误余量估计，并检查货类兼容；大仓库无法补救低产能、错误装卸设置或过慢配送。食品等货物对交付时间的要求可从货物定义核对。[官方货物定义](https://wiki.transportfever3.com/doku.php?id=modding:misc:cargo)

### 仓库无需接路与货物中转规则

2026-10-03 已查阅官方手册，并经用户要求纳入后续规划：**原生仓库本身不需要道路接入，不为使仓库收发货而单独修建接入道路。** 官方明确仓库处于车站覆盖半径内即可与停靠车辆交换货物。[官方仓库说明](https://wiki.transportfever3.com/doku.php?id=gamemanual:infrastructure:warehouses)

- **道路服务车辆进出站**：货车仍须通过实际连通的道路到达货运站；仓库无需接路不代表货车站可以不接路。其他运输方式分别核对轨道、航道或航空路径。
- **中转核对同一库存**：货车转直升机时，货车站和直升机场自身货运终端（或货运直升机坪）必须都能访问同一仓库库存；不要求两个站点互相位于对方覆盖范围内。规划初筛看覆盖，验收读取 `getStationCatchables(station,true)` 的共享 `STOCK_LIST`，再检查装卸记录。
- **货物仍需车辆运输**：仓库不会仅因邻近工厂就自动收取其产品；城市建筑和工厂也不能直接取用仓库内容。货物进出仓库通过停靠车辆完成，后续消费端仍需有效配送线路。直达消费端时不强制另建中转仓。[官方仓库说明](https://wiki.transportfever3.com/doku.php?id=gamemanual:infrastructure:warehouses)
- **货运覆盖与客运通路分别检查**：官方规定货物只需处于站点覆盖半径内，乘客则还需有效通路；不能把客运道路或步行要求套到仓库上。[官方车站覆盖说明](https://wiki.transportfever3.com/doku.php?id=gamemanual:infrastructure:stationsdepots#catchment_area)
- **可覆盖仍需可装卸**：同时检查仓库接受货类、空余容量、车辆承运能力及线路装卸配置。仓库扩容、站点改造后重新读回覆盖关系。本规则不自动授权删除已有道路。

### 主仓库共库检查

每个集合指定一个主仓库，各货运设施分别核对它的同一个真实库存，不两两比较站点覆盖。

1. 规划记录主仓库和参与货运设施；检查各设施对仓库的覆盖并留余量。此时 `inventoryVerified=false`，不填历史库存编号。
2. 建后将主仓库的 `WAREHOUSE` 实体映射到实际 `STOCK_LIST`。覆盖查询返回仓库实体或库存实体时，统一转换成库存ID；仅命中建筑施工实体不算通过。
3. 对每个货运设施读取其原生站点覆盖，至少一个站点访问指定库存才通过。同一原生站点只读取一次，不要求不同设施彼此覆盖。
4. 主仓库只有一个库存时直接选用；有多个不同库存时明确指定 `primaryStockList`，不得让不同设施分别覆盖不同库存就宣称共库。
5. 容量和当前存量按真实库存ID计一次；全图汇总同样去重。不同读取结果冲突时重新采集，不累加成两份库存。

公共实现为 `scripts/primary_warehouse.lua`；陆上集合、联合集合、捕鱼集合及全图共库验收统一调用。规划输出 `sharedWarehousePlans`／`sharedWarehousePlan`，建后输出 `primaryWarehouse`、`primaryStockList`、逐设施覆盖、`inventoryById` 及 `verified`。`commonWarehouseStockIds` 仅包含通过验收的真实库存ID。

共库结果只说明库存访问关系。货品兼容、装卸配置、吞吐估算、维护能力和设施接路分别检查；载具投运按实际出发、正常运行及原生故障结果，不额外验证往返或货物交付数量。

### 先判断运输任务，再决定配套

**仓库不是按“火车站、码头、机场”这些建筑名称一律配建，而是由该处是否需要接收并暂存中转货物决定。** 客运、直接取货、直接交付、中转、购置维护是五类不同任务。同一座综合枢纽可能同时承担几类任务，应逐项检查。

| 该处的任务 | 仓库判断 | 车站/货站判断 |
|---|---|---|
| 只运输乘客 | 不需要货物仓库 | 需要对应方式的客运终端及实际步行/换乘通路；公交/电车接驳按客流决定 |
| 从生产设施直接装货 | 若来源库存已被可装货终端覆盖，不因“取货”额外强制建仓 | 使用现有有效装货终端或新建相应货运站；不在覆盖内则增加集货线路 |
| 向工厂或城市直接交货 | 若目标消费库存确实接受该货物且在可卸货终端覆盖内，不强制加中转仓 | 需要能卸目标货类的终端，核对工厂输入或城市需求；卸到站名所指城市不等于建筑已收到 |
| 卸下后交给另一条线路继续运输 | 配置可接收该货类的共享仓储；已有合格仓库可复用，无须重复新建 | 每一种参与方式都需要相应货运终端。两段若共用同一终端，也须有可读回的有效中转库存，不假定站台自行存货 |
| 仅购车/购船/购机或维护 | 不因这些功能配建仓库 | 购置设施核对出库路径；专用维护核对服务模式、范围和能力，不作为线路货运停靠点 |

“需要仓储”指需要有效中转库存，并非必须新建一座独立建筑：若当前模块已提供相应库存，须读回确认其接受货类、容量和两段线路访问关系后才可复用。不能把站台容量、机库容量或维护池当成仓库容量。未经查证，不把工厂输入库存当成可再出口的通用中转仓。

### 各类建筑配套矩阵

下表为规划判定，仍需按当前终端、模块和覆盖读回。已有配套能满足任务时优先复用；“需要货站”也可以由同一综合设施内已存在的有效终端满足，不一定另造独立建筑。

| 主设施/用途 | 仓库 | 货站、车站及其他配套 | 不应误配的设施 |
|---|---|---|---|
| 客运火车站 | 纯客运不需要 | 铁路接入、客运站台/出入口；客流超出便利步行范围时配公交/电车接驳，换乘点核对步行连通 | 仓库和货车站不能代替客运入口；不为提高客流而建仓 |
| 货运火车站 | 中转时需要共享仓储；直接装生产库存/卸消费库存按[运输任务判断表](#先判断运输任务再决定配套)判断 | 货运站台、轨道、匹配货类的列车；公路集散时需要货车终端，水路集散时需要货运码头 | 并非每座货运铁路站都要另建货车站，只有公路段参与时才需要 |
| 客运码头/渡轮站 | 纯客运不需要 | 客运泊位、城市步行通路；视距离配公交/电车；另核对购船来源及可航行路径 | 船坞不能替代乘客码头 |
| 货运码头/港口 | 转铁路、货车、另一条船线时配置有效中转库存；直送消费端可不另建 | 货运泊位；按下一段配货运铁路站或货车站，均覆盖同一仓库 | 只把客运泊位、仓库和货车站摆在一起，不会自动形成货运港 |
| 固定翼客运机场 | 纯客运不需要 | 匹配机型的机场运行模块、客运终端、出入口；公交/电车/铁路接驳按完整旅程选取 | 客运机场有机库不代表能处理货物 |
| 固定翼货运机场 | 需要中转时配仓储；直接覆盖生产/消费库存时按实际可用性判断 | 可处理目标货类的航空终端和飞机；公路/铁路集疏运分别需要对应货运终端 | 仓库在机场维护圈内，不等于在航空货站货物覆盖内 |
| 直升机场（heliport，含购机维修） | 纯客运/购机维修不需要；货运中转按共享库存判断 | 接通道路，复用机场自身客货终端；核对步行通路、库存覆盖、线路和载具；有公路集散段时再核对货车终端 | 已有直升机场能完成客货停靠时，不在旁边重复建小型停机坪；维护圈不等于货物覆盖 |
| 客运直升机坪 | 纯客运不需要 | 支持乘客的终端、步行/公交接驳；购机维修基地另按服务范围安排 | 小型停机坪不等于购机机库 |
| 货运直升机坪 | 换装时需要共享仓储；直接取生产库存或交消费库存不机械加仓 | 支持货运的停机坪、能装该货物的直升机；来源/目的地需公路运输时各配货车终端 | 不用基地800米维修圈代替小型停机坪货物覆盖 |
| 公交/电车站、客运枢纽 | 纯客运不需要 | 对应道路/轨道、方向正确的停靠点、步行连接；车库和维护按运营需要配 | 客运站不能因靠近仓库就成为装货站 |
| 货车站/货运电车终端 | 用于中转时需要仓储；直装直卸按[运输任务判断表](#先判断运输任务再决定配套)判断 | 对应运输模式的道路/轨道、车辆、装卸权限；确认终端及车辆都兼容目标货类 | 仅卸货点不能假定可回程装货；通用道路货站不能假定支持货运电车 |
| 仓库本身 | 已是储存设施，仍需核对货类/模块/容量 | 至少有服务其收发任务的有效货运终端；跨方式中转时各段终端覆盖同一库存，并配置车辆和线路 | 仓库不是一条运输线路，也不会代替远处城市的配送终端 |
| 公路/电车/铁路购车库 | 不需要货物仓库 | 相应网络接入与出库到运营线路的路径；线路上另有实际客/货站 | 车库不可充当货运卸货站或客运站 |
| 船坞 | 不需要货物仓库 | 出坞水路、兼容船型；运营线路另有客/货泊位 | 不因船坞兼有维护能力就省略货运码头 |
| 机场机库/直升机购机维修基地 | 单纯购机维修不需要 | 出库/机型兼容及维护覆盖；若基地另承担客货停靠，再按对应运输用途配套 | 购机、停靠、装卸、维护四种功能分别核对 |
| 道路/铁路/船舶专用维护站 | 不需要货物仓库 | 匹配车辆模式及有效维护覆盖；是否需要道路/水域接入按该资源实际定义核对 | 不额外给维护站建“维修物资仓”或货运线，除非当前模组明确要求且已验证 |

### 三种可复用的配套方案

**直接供给：可以不建中转仓。**

```text
生产库存（来源货运终端覆盖）
  → 车辆运输 → 消费库存（目的货运终端覆盖且接受该货物）
```

这可以是公路、铁路、水路或航空的规划候选；具体组合是否可用仍要检查对应终端与库存，本文不宣称所有站型都已运行验证。农场已有可用装货位时可复用，不重复建同用途货站；末端覆盖不足则需要配送段。

**两种交通方式中转：一座共享仓库，两个有效货运终端。**

```text
来源 → 货车 → 货车站A ──卸入──> 仓库W ──取货──> 铁路/水运/航空货站B → 干线
                         A和B的货物覆盖都包含W的库存
```

不是要求两站中心互相位于对方的半径内，而是要检查**同一实际仓库库存**能否被两站访问；不能只看圈有交集或建筑外轮廓压线。终端间还可能需要真实道路、轨道、步行或航道连接，这些按各自交通功能检查，与库存覆盖分开。

**干线两端都需要集货/配送：两端各形成一个中转组合。**

```text
农场 → 集货货车 → 来源货车站/共享仓库/直升机场或货运直升机坪
     → 直升机 → 目的直升机场或货运直升机坪/共享仓库/配送货车站
     → 配送货车 → 覆盖城市需求建筑的卸货点
```

这是徐州已完成换装和城市消费验收的类型。生产设施或城市消费库存若恰好能由干线终端直接服务，可以省掉相应一端的公路中转，不能照抄完整组合增加无用建筑。反之，仅建城市到货仓也不等于全城供给完成，须检查实际消费建筑覆盖及配送结果。

### 配套数量、摆放顺序和环境取舍

1. **先列运输段和接收库存**：每段来源、目的地、货类、装/卸终端，以及直接交付还是中转都要明确。客运单独列步行和换乘段。
2. **优先复用有效设施**：检查现有终端的模式、货类与方向，再决定缺多少座。多条线路可共享终端/仓库时，按实际排队、库存拥堵和扩建余量决定是否分开，不强制一线一站一仓。
3. **先定共同覆盖，再预留升级**：仓库放在参与中转终端可访问的范围内，给仓库扩建、站台/泊位延长、车辆转弯和维护位置留余地。不要为了凑覆盖挤进住宅或锁死主设施扩建。
4. **把外部接驳列为独立工程**：已有原生道路端口不等于外部接通；车辆使用的公路/轨道/水路与出库路线分别验收。原生仓库无需单独接路，按[仓库中转规则](#仓库无需接路与货物中转规则)核对库存覆盖；模组改变规则时须另查定义。
5. **噪声与污染仍要比较**：换装越多，可能增加装卸、等待、车辆行驶及设施占地。优先减少没有实际运输用途的仓库和终端；繁忙集散点避免贴近住宅，使用合适末端配送，但不把搬到城边视为消除市政区域污染。
6. **容量由吞吐决定**：先核对仓库货类与有效空余容量，再观察批量到货、班次间隔、装卸速度和配送积压。维护池、泊位数、乘客容量不能计入货物库容。

### 仓库与车站联合选址

2026-10-03 用户确认：仓库、车站和直升机场等参与中转的设施应作为一个组合联合选址，以有效覆盖、顺畅通行和扩建余量为目标，不单独追求建筑之间距离最短。

1. **先确定车站入口与道路走向**：货车站优先靠近既有道路，入口朝向车辆主要来向，减少绕行、急弯和掉头；同时检查设施实际入口和道路连接；返程不列入常规载具投运验收。道路优先直线或平滑曲线，延路优先沿原方向直延。
2. **在共同覆盖区布置仓库**：利用仓库无需接路的特点，灵活放入所有参与终端的共同货物覆盖区，尽量留出覆盖余量，不刚好压线。最终须核对各站点能访问同一实际库存，不能仅凭几何圆圈判断。
3. **联合调整位置与朝向**：仓库不得占用机场降落平台扩建槽位，也应避让货车站延长、增设出入口和道路接驳空间。共同覆盖、车辆通路和升级预留任一不满足时，返回调整整个组合。
4. **优先复用并按需求配容量**：可共用有效终端和仓库的线路优先复用；按货类、批量到货、班次间隔及需求确定容量。运行后根据排队和库存积压，区分需要扩站、扩仓还是调整运力，避免机械地一线一站一仓。
5. **区分客货选址目标**：货运组合优先靠近城市外部道路，避开预计住宅扩张方向，并评估噪声、污染和末端配送时间。客运车站重点考虑步行覆盖、有效通路和换乘距离，不机械套用城外选址；直升机场的暂定500米基准不推广为所有车站的距离规则。

本项目航空供给组合的规划顺序为：**预选直升机场及接路走廊 → 联合确定货车站入口 → 在共同覆盖区布置仓库 → 检查扩建空间 → 预览与验收**。这是可迭代的规划顺序，施工按实体依赖分阶段执行；设施建成后重新解析实际端口和库存。参见[航空联合选址流程](TRANSPORT_AIR_SITING.md#直升机场选址与道路同步规划)。本规则用于后续规划，不自动授权迁移已有设施。

### 施工清单与验收证据

每次方案增加“配套是否缺失”一栏，至少写明：

| 要核对的项 | 合格证据 |
|---|---|
| 终端处理能力 | 运输模式、目标货类、允许装/卸或乘客上下车与拟用载具匹配 |
| 来源/消费端 | 实际来源库存有该货物；实际接收库存接受该货物，且消费端确有需求 |
| 中转仓 | 对应库存实体、兼容货类、容量，以及所有参与终端的货物覆盖交集 |
| 集疏运 | 需要的货车/铁路/船舶/航空段均已配置，含末端消费段；不是只建空站 |
| 客运接驳 | 入口、步行/换乘通路和需要的接驳线路实际可达 |
| 配套维护 | 各载具维护模式匹配；覆盖与状态恢复按[维护验收](TRANSPORT_MAINTENANCE.md#维护验收)验证 |
| 实际结果 | 中转仓卸入、下一段载具取货、最后消费端卸货/消费；纯客运检查真实乘降 |

本节依据前文的共享库存机制、徐州运行证据及原生终端客货标记作分类推导；不是对全部站型的新实机验收。若特定站型或模组的库存/装卸行为不明，标记待验证，不擅自宣称能直送或能免仓。不得仅凭客运站间换乘映射、维护覆盖或 `noPath=false` 判断货运配套齐全。

来源与未验证范围见[总览的来源说明](TRANSPORT_FACILITY_SITING.md#来源与待核对范围)。
