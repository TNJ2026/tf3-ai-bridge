# Transport Fever 3 城市发展策略

整理日期：2026-10-01。

本文依据 TF3 官方开发博客和货物机制文档整理，区分已公布机制与经营建议。具体数值和机制开关以当前游戏版本、模组及存档设置为准。本文不构成实时地图施工方案。

## 1. 核心思路

采用“一个重点城市＋邻近城市协同，分批扩张”的发展方式。以稳定供货和市内公交为基础，尽早比较有实际需求的城际连接，持续改善运输质量和环境评分。长期供给体系和扩建空间整体规划，设施与运力按需求分期投入。

增加道路和车辆是手段。发展目标应是让有效交付与乘客运输持续增加，同时控制等待、拥堵、噪声和污染。

## 2. 已公布的成长机制

官方城市发展说明介绍了以下机制：

- 城市有 18 个成长等级，运输乘客和供应城市需要的货物会获得成长经验。
- 城际乘客比市内乘客提供更多经验。
- 城市需求随规模变化；生产链更复杂的需求货物，交付后提供更多经验。
- 六项城市评分影响成长经验的效果：声誉、乘客满意度、交付、交通、噪声、污染。

来源：[官方城市发展说明](https://www.transportfever3.com/news/dev-blog-episode-4-tycoon/)。

因此，经营上应同时关注运输数量与服务质量。不能把线路盈利、车辆数量或基础设施规模直接当作城市成长效果。

## 3. 分阶段发展策略

以下为根据官方机制推导的经营建议，不是固定建造顺序或精确数值公式。

### 3.1 起步：基本供货与市内公交

先查看城市实际需求，从附近选择运输距离短、加工环节少的供应链，建立持续交付能力。避免一开始同时铺设多条尚未验证需求的产业线路。

市内公交应连接住宅、商业和工作区域，并预留城际站接驳。线路尽量直接，避免一条绕全城的大环线承担所有出行。

这一阶段主要目标是降低投资和调试难度，建立可扩张的基础。官方货运介绍也将小聚落的基本供货视为成长起点。

来源：[官方货运系统介绍](https://www.transportfever3.com/news/first-look-episode-2-industries-and-cargo/)。

### 3.2 成长：接入邻近城市的客运网络

建立基本市内接驳后，尽早比较有实际客流的城际连接，无需等重点城市所有需求都满足或发展到最高等级。距离较近、客流较小时，可先比较公路客运方案；客流集中、距离更长时，再比较铁路的收益和成本。

推荐的网络结构：

> 住宅／商业区 → 市内公交 → 城际站 → 邻城的公交网络

评价线路时应看整个旅程，包括步行、等车、换乘和乘车。列车速度高，但接驳绕路或等待过长，仍可能影响乘客满意度。

官方确认，旅行时间和舒适度会影响城市满意度及长期成长。

来源：[官方基础设施介绍](https://www.transportfever3.com/news/first_look_episode_3_infrastructure/)。

### 3.3 扩张：补充新增需求，处理实际瓶颈

每次城市升级后，重新检查货物需求、供应情况和六项评分。按实际瓶颈安排投资：

| 观察到的问题 | 优先行动 |
| --- | --- |
| 需求货物长期缺货 | 检查原料、生产、装载、运输和末端配送哪个环节不足 |
| 乘客持续积压 | 检查班次、运力、堵车和换乘等待 |
| 车辆很多却运输缓慢 | 改善路线、路口或站点吞吐，再决定是否加车 |
| 运输量增加但成长缓慢 | 查看六项评分中拖后腿的项目 |
| 基本供应和市内客运已稳定 | 比较新增城际客运与复杂需求货物链的投入收益 |

货物时效需要单独检查。官方货物定义中，每种货物都有预期运输时限，超过时限会影响客户满意度。对时效敏感的货物，减少等待和中转通常比单纯增加库存更有价值。

来源：[官方货物机制文档](https://wiki.transportfever3.com/doku.php?id=modding%3Amisc%3Acargo)。

### 3.4 大城市：提高单位车辆的运输效率

中后期可将大量货物集中到干线运输，再通过短距离配送覆盖城区；客运逐步形成主干线与接驳线。

仓储和专用装卸设施应针对实际瓶颈建设。例如，先判断限制来自供货不足、装卸等待、道路拥堵还是运输能力，再选择扩容手段。

枢纽选址需要平衡接近性与噪声：靠近住宅方便乘车，但可能增加噪声；放得太远，又会拉长接驳。污染按整个市政区域统计，仅把设施移到城区边缘不能解决区域污染问题。

来源：[官方货运系统介绍](https://www.transportfever3.com/news/first-look-episode-2-industries-and-cargo/)、[官方城市评分说明](https://www.transportfever3.com/news/dev-blog-episode-4-tycoon/)。

### 3.5 各阶段通用：预留设施升级空间

从首次选址开始，就应考虑设施升级后的占用面积，尽量保留连续的扩建空间。根据合理的后续运量，结合原生模块槽位与实际尺寸，预留仓储扩容、站台或股道延伸、泊位增设的方向；同时保留出入口、道路与铁路接驳通道，以及港口所需岸线和船舶进出水域。

方案中应区分当前占地与升级预留区域。新增道路、铁路和其他建筑尽量避开主要扩建方向，避免日后扩容需要大规模拆迁或中断运输。尺寸未知时注明估算依据；受地形、岸线或既有建设限制时，说明升级上限、可能的迁改及替代位置。预留空间不等于提前建设，也不代表升级方案已经通过碰撞校验。

具体要求见 [规划手册：设施升级空间预留](../guides/AGENT_PLAYBOOK.md#33-设施升级空间预留)；接口能力与验证边界见 [设施配置与建造说明](../reference/FACILITY_SUPPORT.md)。

### 3.6 各阶段通用：维护与持续运营

官方已说明车辆会随时间磨损，忽视维护会产生后果。因此，运力规划应同时考虑维护需求，不能只比较购置价格、载量和速度。

来源：[官方基础设施介绍](https://www.transportfever3.com/news/first_look_episode_3_infrastructure/)。

经营上，建议定期检查车辆状态、维护设施是否适用且能实际提供服务，以及维护能力能否跟上车队规模。比较加车、更新车辆或增设维护设施时，应计入运行与维护成本，并观察维护安排对班次和有效运力的影响。设施已经建成不代表车辆已经获得维护，具体服务规则和效果应以当前游戏数据核实。

## 4. 区域协同与全城长期供给规划

### 4.1 重点城市带动邻城，按投资效果扩张

以下是经营建议，不是游戏强制的发展顺序。

| 发展方式 | 优点 | 主要限制 | 建议用途 |
| --- | --- | --- | --- |
| 所有城市同时发展 | 较早形成区域运输网络 | 资金和管理精力分散，多条供应链可能同时不足 | 收入稳定、已有成熟运输体系后逐步展开 |
| 先集中发展一城，再向外扩张 | 起步成本和调试范围可控 | 若一直等待单城发展完成，会推迟有价值的城际连接 | 用于建立最初的供货与配送闭环 |
| 重点城市＋邻近城市协同 | 集中投资，同时利用城际客流和共享供应链 | 需要明确各城需求及货物分配 | 作为默认的区域发展方式 |

官方说明，公司等级与世界人口增长有关，城际乘客比市内乘客提供更多成长经验。因此，重点城市稳定起步后，应比较一两个条件合适的邻城连接。“带动”通过真实客运、共享供应链和末端配送实现，不能假定主城变大就会使邻城自动成长。

来源：[官方发展机制](https://www.transportfever3.com/news/dev-blog-episode-4-tycoon/)。

每轮投资比较主城扩容与邻城新增服务带来的有效运输增量、完整成本及评分影响。若主城扩容需要昂贵拆迁，而邻城只需较小投入便能获得稳定服务，可优先发展邻城。反之，现有供给链尚未接通或持续失衡时，先解决瓶颈，再扩大规模。复制已验证的运营方式，不机械复制设施大小或车辆数量。

共享供应链必须核算各城合计需求，并检查实际分配，避免前站取走过多货物使后站长期缺货。

### 4.2 全城后期供给整体规划、滚动修正

以目标城市规模和可能的扩张方向规划完整供给体系，区分当前已确认需求与后期预测需求。城市升级、产业变化或新区形成后重新核对，不能把预测当作固定的货物清单或精确需求量。

每座重点城市的规划应形成长期布局图和以下供给对照表：

| 规划项目 | 需要记录的内容 |
| --- | --- |
| 目标与需求 | 目标规模、货物种类、需求量或估计区间、已确认/预测状态及依据 |
| 生产来源 | 原料产地、加工链、可供产量、共享供应的其他城市及必要的替代来源 |
| 干线运输 | 水运、铁路或公路方案，预计批量、班次和运输时效 |
| 仓储与换装 | 服务哪些货物和片区、到货波动、装卸能力与所需缓冲容量 |
| 城区配送 | 现有及潜在扩张片区、配送站位置、实际覆盖与末端运输能力 |
| 扩容安排 | 当前建设、后续预留、扩建方向及需求/库存/吞吐触发条件 |

优先预留后期难以补建的连续用地、岸线、铁路走廊和出入口。运力、仓库及站台按实际需求逐步投入；持续缺货、库存趋势异常或设施接近有效吞吐上限时，先定位瓶颈，再启动对应扩建。关键货物可规划备用来源或路线，但无需起步时全部建成。

## 5. 运输能力与仓储容量的平衡

### 5.1 先匹配持续流量，再确定缓冲容量

以鱼类供给为例，逐段核算“渔场可供货量 → 船运 → 港口装卸与仓储 → 货车配送 → 城市实际需求”。所有流量统一使用相同的游戏时间单位，采用实际运行、装卸和维护后的有效能力，不只看车辆标称载量。

对于单一货物、稳定运行的运输链，可用以下关系辅助规划；它不是游戏内部的精确计算公式：

> 持续有效交付量 ≤ 可供货量、各段运输能力、装卸能力、实际需求中的最小值。

有加工环节时，按当前配方和产量将原料、半成品能力换算成目标成品的等效产出，不能直接比较不同货物的数量。多城共享时，要把共用路段承担的各支线货量一起核算。

仓库用于缓冲批量到货与连续配送的时间差。对同一货物、同一统计窗口，库存变化可按“入库量－出库量”核对；有生产消耗或其他增减项时另行计入。库存长期上涨说明输入与输出失衡，扩大仓库只会延后满仓，不能提高持续交付能力。

### 5.2 按到货批量和库存波动配仓

根据实际到货批量、到货间隔、配送速度及延误波动估算库存峰值，再设置合理缓冲余量。分别检查货类适配、可用容量与装卸吞吐；总库容足够不代表特定货物有空间，也不代表装卸足够快。

规划示例（并非游戏固定数值）：城市每个游戏分钟消耗 10 单位鱼，一艘船每 10 分钟送到 100 单位，平均供需平衡。若船舶集中卸货而货车不能立即接走，到港时可能需要接近一船货物的缓冲空间，具体峰值取决于装卸速度与到港前库存。若每次运来 200 单位而有效出库仍为每分钟 10 单位，库存会逐批上涨，应减少输入或增加有实际需求的去向。

食品应特别关注周转和全程交付时间。官方货物定义包含预期运输时限，长时间等待可能影响客户满意度；因此不能以“库存越多越好”为目标。只有到货峰值不足以容纳、且长期进出基本平衡时，扩仓才是直接的解决办法之一。

来源：[官方货物时效定义](https://wiki.transportfever3.com/doku.php?id=modding%3Amisc%3Acargo)。

| 观察结果 | 优先检查或调整 |
| --- | --- |
| 库存持续上涨，市区仍缺货 | 换装是否接通、装卸配置、末端运力、道路及需求覆盖 |
| 仓库经常空，车辆等货，市区缺货 | 原料供给、加工产量、上游班次和运输连接 |
| 每次到货时容量不足，之后逐渐清空 | 增加缓冲容量，或减小单次批量、提高到货频率，并比较新增成本 |
| 库存充足，城市需求已满足 | 减少输入，或分配给确有需求的其他城市 |
| 库存不多，但交付耗时长 | 绕路、等满载、装卸排队和多次中转，避免无效扩仓 |

## 6. 生产设施结构与铁路产业园

### 6.1 原料产地分散，相关加工集中，成品分城配送

建议按产业链和运输距离组织生产设施。优先利用现有矿场、林场、渔场等原料来源，将适合集中且上下游联系紧密的加工设施组成产业园，以铁路或水运汇集原料、向多个城市发运成品。

| 设施 | 建议布局与职责 |
| --- | --- |
| 原料来源 | 利用适合的产地，组织原料集运；不要仅为集中布局而迁入园区 |
| 相关加工厂 | 按实际配方组成相邻组团，减少中间品绕行与换装 |
| 原料仓储 | 靠近接收与加工环节，缓冲干线到货波动 |
| 成品仓储 | 靠近发运区，按货类及服务城市组织周转 |
| 铁路货站及公路装卸区 | 为原料到达、成品发运和短途接驳预留各自空间，按吞吐决定是否分站 |
| 车库与维护设施 | 共享交通走廊，按车型、服务能力和车队规模分期配置 |
| 城市配送站 | 布置在实际需求片区，负责末端交付 |

概念结构如下，具体货流可按需求直达，不要求每批货物都经过全部仓储环节：

```text
多个原料产地
    ↓ 铁路／水运集运
原料接收与缓冲仓储
    ↓
相关加工厂组团
    ↓
成品仓储与发运区
    ↓ 铁路干线
各城市货站 → 短途配送 → 有需求的城市建筑
```

相邻布置不代表自动连接。厂区、仓库和货站之间的覆盖、货物转移、装卸能力及运输路径必须逐项验证。

### 6.2 集中布局的边界与选址条件

集中有利于汇集铁路货量和复用设施，但应比较全链条的运输距离、换装次数、时效、建设与维护成本。原本靠近原料和消费地的工厂可能更适合保留；食品等时效敏感货物不应仅为经过园区而增加中转。

产业园选址应检查平整用地、铁路接入坡度和曲线、道路通道、市政边界及扩建方向。水铁联运方案还需检查岸线和水域。预留股道延伸、站台增设、仓库扩建和厂区扩容空间，避免所有货流共用一个无法扩展的装卸口。

污染按整个市政区域统计，把工厂放在城外不等于消除对城市评分的影响。产业集中时仍需评估所在市政区域和邻近住宅的环境代价。

官方明确沙盒模式可以自由放置产业；这不证明普通经营模式允许随意迁厂，也不代表可直接搬走既有工厂。执行前需核实当前模式、产业规则及可用操作。当前桥接接口尚未支持工业设施迁建，产业园规划不能直接作为迁建脚本执行。

来源：[官方市政区域与沙盒模式说明](https://www.transportfever3.com/news/dev-blog-episode-4-tycoon/)。接口限制见 [设施支持范围](../reference/FACILITY_SUPPORT.md)。

## 7. 持续观察的指标

每轮扩建后，观察完整运输周期，确认问题是否改善，再进行下一轮投资。

| 指标 | 要回答的问题 |
| --- | --- |
| 城市等级与成长经验 | 城市是否持续成长，运输增加后成长效果是否改善？ |
| 各类货物需求与实际交付 | 哪类货物短缺，供应能否跟上人口增长？ |
| 货物运输时间 | 时间主要消耗在行驶、装卸还是等待？ |
| 库存趋势与到货峰值 | 入库和出库是否长期平衡，短时容量不足还是持续积压？ |
| 各段有效吞吐与多城分配 | 哪个环节限制交付，共享供应是否使部分城市长期缺货？ |
| 站点乘客积压与车辆利用率 | 运力不足、班次不均，还是线路设计不合理？ |
| 车辆磨损与维护服务 | 哪些车辆需要维护，现有设施是否适用并实际提供服务，维护能力是否充足？ |
| 六项城市评分 | 当前最值得改善的是哪一项？ |
| 线路收益、运行维护与扩建成本 | 计入持续运营和维护费用后，下一笔投资能否承担，并带来有效运输增量？ |
| 设施升级空间 | 后续扩建所需的占地、出入口和接驳通道是否仍然保留？ |

## 8. 将策略落实为当前城市方案

每次换图或切换重点城市，先填写 [发展方案模板](DEVELOPMENT_PLAN_TEMPLATE.md)。从当前存档重新确认城市、需求、资源、资金与线路；历史城市的成功线路只能用来参考方法。

第一阶段先完成调查与候选比较，再选择一个可验证的小规模闭环。内部公交和供给线没有固定先后：已有供给设施尚未接通时优先修通有效交付；客流明确、接驳短且成本低时可先开公交。比较时计入站点、接驳路、车辆、车库、维护及运营支出，不能只比较线路长度。

每阶段都指定交付物、进入条件和完成证据。未观察到实际运输前，不把“已建成”写成“供给稳定”；后期供给按已确认需求与预测情景分别记账，升级后滚动更新。

牡丹江旧地图的调查线索已移至 [历史案例](../history/MUDANJIANG_CASE.md)，不作为当前城市的默认建设清单。
