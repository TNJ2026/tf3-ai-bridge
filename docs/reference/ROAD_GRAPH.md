## 公共入口

- `get_network_template(template)`：原生车道宽度、偏移、方向、模式和道路样式。
- `list_road_structures()`：当前原生桥梁/隧道资源；不能凭资源存在认定任意跨度可建。
- `preview_road_graph(graph, isolated_test)`：编译、检查并产生 60 秒单次令牌。
- `preview_dual_highway(centerline, template, median_gap=4, drive_side="right", isolated_test=false)`：读取原生高速模板，生成成对道路并调用道路图预览；返回四个端口及两个方向的节点序列。
- `commit_road_graph(preview_token, backup_save)`：单次提交，备份名称须由执行者事先核对保存成功。参数本身不证明文件存在，也不执行存档重载。
- `get_road_graph_operation(operation_id)`：以预览令牌读取原操作记录，不重发；不是重新独立验收接口。

主机与游戏均校验字段；游戏编译阶段进一步校验原生组件、归属、冻结状态和车道。接收器为 `preview_road_graph` 单独开放 8192 字节，其余命令限额不扩大。更大的工程必须先整体设计、再按明确依赖拆成批次。旧接收器不会因此获得新能力，安装后必须重载，并查询实际能力版本。

## 道路图格式

`nodes` 下标从 **0** 开始，每个节点恰选一种来源：

```json
{
  "nodes": [
    {"node": 123},
    {"split": {"edge": 456, "param": 0.5}},
    {"position": {"x": 100, "y": 200, "z": 8}}
  ],
  "edges": [
    {"from": 0, "to": 1, "template": "country/country_new_small"},
    {"from": 1, "to": 2, "template": "country/country_new_small"}
  ]
}
```

示例编号及资源须现场重新解析，不能直接提交。坐标必须含有限 `x/y/z`。最多 32 个输入节点、48 条输入边；每条新边平面跨度 10～200 米，批次新边总长不超过 3000 米，端点坡度不超过 12%。每条原路每批最多切分一次，切分参数 0.05～0.95，切分后每段平面距离至少 5 米。不得有重复节点、重复边或孤立输入节点。

边可提供三维 `tangent0/tangent1`。省略时采用直线弦向量；平滑曲线应显式提供一致的切线。桥隧另加 `structure="bridge"|"tunnel"`、`structure_resource`；普通地面为 `ground`。桥隧跨度、净空、引坡、地层等仍由原生检查及现场验收决定。立体交叉使用分离节点及高程，不靠 XY 重合创建路口。

双向高速不会把单向模板当作双向公路。按模板车辆车道实际 `forward` 处理正反向；按宽度和偏移保守确定道路中心间距。中央净间隔是规划参数，不是通用工程标准。中心线逆折、急弯、自交和道路重叠拒绝；平滑切线随偏移后路径生成。匝道和两端接入需要在道路图中明确设计，四个端口不会自动互接或掉头。

实机中型高速车道宽度为 `[4,5,5,4]`、offset 均为 0，包含两侧路肩。offset 不是绝对横向位置；主机按全部车道宽度之和再加两倍最大绝对偏移计算保守包络。该模板宽 18 米、中央间隔 4 米时，两幅中心距为 22 米。已加入真实零偏移回归用例。

v35 对单向道路逆向路径查询会因没有入口/出口方向车道返回 Lua 校验错误，实测未触发施工或引擎崩溃。v36 将该情况改为结构化 `pathFound=false`、`directedLanesAvailable=false`、`nativeQueries=0` 及原因；没有调用原生寻路，不能宣称原生搜索得到否定结果。v36 已在验收存档重载后完成高速两幅、匝道与单向环路共 8 项 CAR/TRUCK 逆向检查。大型路口不要一次读取完整 `TRANSPORT_NETWORK`：五岔口实测超过 65536 字节响应上限，应读取节点配置并逐项调用有向路径检查，或使用分页组件读取。

## 提交与读回

预览签名包含道路图、旧路完整快照与归属、原节点位置/配置、原生模板车道和样式。重新载入、手改、道路替换或预览过期后重新解析。令牌先消费，再重读并检查身份，最后单次发送；异常、超时或部分成功保留 pending，不能自动重发。

**切分提案不调用 `makeProposalData`。** 该接口对移除路段存在已知原生断言，不能靠 `pcall` 保护。切分预览返回 `structural_only=true`、`nativePreviewPassed=false`、`collisionsUnchecked=true`；隔离测试阶段必须额外检查施工走廊，不能把此返回当作已通过原生碰撞检查。

静态读回包括新边数量、实际端点、位置/切线、模板、车道、样式、桥隧类型、交通网络、未替换旧路完整快照、切分旧路消失，以及转向/横道/信号策略和真实邻接集合。自动信号可重新生成，但每个阶段必须有合法时长和有效转向索引。原生 userdata 经明确记录模式快照，不用对象地址作签名。

`verified=true` 仅表示以上静态验收；`directedPathsVerified=false`、`serviceConnectivityVerified=false` 保持独立。须额外按 CAR/TRUCK（涉及公交、电车时再加入相应模式）逐项核对每个路口的实际有向路径，并检查车辆实际行驶、短时模拟和保存。重载、长期模拟稳定性未由离线测试证明。

## 隔离验收清单

1. 保留当前正式现场备份与独立隔离槽；仅在用户批准后手动载入隔离槽。
2. 核对会话、存档身份、暂停状态、v35 能力、模板实际车道及桥隧资源。重载前实体编号全部失效。
3. 在无现有建筑/线路的测试区，依次验证新建直路、端点延伸、T/Y、十字、多路节点、默认隐式配置、带横道节点。
4. 对无对象普通道路测试曲线切分、两端原配置引用和新路口；禁止把移除提案送入原生预览。
5. 验证单向合流/分流、环岛、两幅高速的相反方向及独立匝道；核查主线无意外掉头或跨幅连接。
6. 桥、隧道、设施外部端口、电车兼容分别测试，不能用普通地面通过来替代。
7. 每例原生单次提交、独立组件/有向路径验收；异常立即停批。短时运行后暂停复查、保存。未通过的组合继续标为待验收。
