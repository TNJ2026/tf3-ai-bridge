# 局部地形平整接口

桥接源码版本：0.12.9。只适用于 TF3。优先选择天然平地，天然平地不满足要求时才考虑本接口；只规划不调用提交。

## 支持范围

- 以世界坐标指定矩形和目标高程（米）。范围向外对齐基础地形网格，边界上的顶点也包含在修改中。已测地图网格为4米，实际调用读取当前分辨率。
- 矩形内统一高程；`transition_width` 默认0，保持原来的硬边界行为。设为正数时，按距平台矩形的欧氏距离，用 smoothstep 插值混合目标高程与施工前原地形，形成圆角过渡带；宽度至少为两个基础网格单元，最多128米。过渡带以外另保留至少16米保护带，保持原高程。地形高程按原生量化精度取整，不提供填水、拆除或修路。
- 最大每轴600米、调查顶点20000个；`max_height_change` 默认10米，允许0.05～50米；`max_edge_grade` 默认0.10，允许0.01～0.20。这些是接口保守限制，不是原生可建保证。
- 影响区内道路、建筑、模型（包括树木）或未知包围盒均阻止提交。水面、目标高程低于水位加1米、基础与表面高程差超过0.25米、边界衔接过陡也阻止提交。启用过渡时同时检查过渡带网格单元的二维坡度保守上界，不能仅检查平台边缘；原地形本身很陡也可能被拒绝。基础与表面高差可能来自微地形，不能一律解释为建筑对齐。
- 原生 `makeProposalData` 在已测游戏绑定中仅接收 `SimpleProposal`，拒绝地形所需的完整 `Proposal`。因此预览明确返回 `validation=structural_only`、`native_preview=false`，不能称原生联合预览通过。提交使用引擎正常校验，不使用 `ignoreErrors`。

## 调用顺序

1. 确认当前会话、地图、建造授权；调用 `get_terrain_operation_capabilities` 检查当前加载版本的能力。
2. `preview_flatten_terrain(bounds, target_height, max_height_change=10, max_edge_grade=0.10, transition_width=0)`：只读检查，返回对齐后的 `flattened_bounds`、保护范围 `affected_bounds`、估算挖填、边缘坡度和阻塞原因。无阻塞且确有变化时返回60秒单次令牌。不得以重复试错替代边坡设计。
3. `commit_flatten_terrain(preview_token)`：MCP 自动创建独立 `tf3_terrain_before_<uuid>` 原生存档，使用空保存回调；确认新文件非空且写入稳定后再执行一次该令牌对应的施工计划。平台只提交一次；过渡带因原生网格无逐点写入方法，按同高程连续行段分成不重叠小块，最多256次原生提交。每块只提交一次，成功回调且逐点读回通过才继续；任何错误、未确认回调或高程不符立即停止，不自动重试或回滚。备份未确认则不提交，保存期间令牌过期则重新预览。令牌在校验时消耗，提交前重新核对会话、地形版本、每个采样点和障碍。
4. 提交返回 `operation_id`（与令牌相同）、备份路径、`receipt` 和读回结果。`completed_steps/total_steps` 表示已验证进度；`get_terrain_operation(operation_id)` 可重查回调及全部基础网格顶点。部分完成仍返回 `needs_reconciliation`，不得当作全部完成。超时或未知结果不重发；当前桥接状态内有未确认操作时阻止下一次提交。
5. 平整后获取新局部快照，重新检查表面地形、实际道路端口及集合布局，再做设施与道路原生预览。MCP 对提交请求（包括错误和超时）失效地图缓存。

`verified` 表示成功回调且基础网格修改区/保护带读回符合预期，误差容限为高程量化步长加0.025米。它不保证高分辨率表面完全平坦、集合可建或长期模拟安全。保存 `receipt` 供异常核对；令牌与操作记录保存在游戏脚本状态中，跨引擎请求可读取；GUI 会话标记变化会失效旧令牌。存档只包含保存时的操作记录，未知旧操作不能以重新预览作为重试依据。只读核对存档、receipt 与当前地形后再决定下一步。

## 2026-10-04 验证记录

来源为本机游戏自带 `api/tealdef/api/type.d.tl`、`cmd.d.tl` 和 `engine.d.tl`，以及获用户明确授权的独立测试地图。

- `GridVec2f.at()` 返回副本，修改它不写回网格。未初始化的网格会将范围变为零高程，不能用于平整。
- 使用 `GridVec2f.new(ix,iy,nx,ny,Vec2f(z,z))` 初始化所有格点，将 `Proposal.terrain.baseHeightMod` 设置为该网格；`ix/iy` 为世界坐标除基础网格分辨率。相等的两个分量已校准为指定米制高程；不推广到未校准的不相等分量。
- 干净测试地图上矩形 `(-2000,-2000)` 至 `(-1996,-1996)` 调整到5.4米：一次提交成功，100个修改区及保护带顶点全部匹配，最大误差约0.000002米，同令牌重放被拒绝。原始备份为 `tf3_terrain_clean_before_20261004`；实测记录在 `exports/terrain_adapter_20261004/live_validation.json`（本机验证产物）。
- 0.12.7 正式分步调用发现模块局部令牌不能可靠跨引擎请求保存，提交在发送原生命令前被拒绝，现场高程未变。0.12.8 改用游戏脚本状态保存令牌、操作和未确认标记；补充模块重建、状态序列化、重放及换会话测试。相关测试110项通过。
- 0.12.8 重载后通过正式 Python MCP 工具包装器完成独立自动备份、预检、单次提交及独立请求读回：同一4×4米矩形平整到5.5米，修改区与16米保护带共100个顶点全部匹配，最大误差0米；重复令牌被拒绝，随后读回仍通过。备份槽为 `tf3_terrain_before_6430e40562a64933a26af1deaeda0345`；完工槽为 `tf3_terrain_adapter_auto_20261004`，确认本次更新并写入稳定。完整记录在 `exports/terrain_adapter_20261004/formal_wrapper_0128.json`。此验证覆盖工具包装器与实时游戏桥接，不代表当前客户端已刷新工具列表。
- 0.12.9 边坡过渡在测试地图通过隔离热加载实测：4×4米平台到5.6米、16米过渡带、外侧16米保护带；32个原生步骤全部完成，324个顶点读回无不匹配，最大误差约0.000005米。证据在 `exports/terrain_adapter_20261004/slope_live_validation.json`；备份槽 `tf3_slope_integration_before_20261004`。常驻桥接仍需重载至0.12.9，客户端需刷新新参数。
- 前一测试存档曾在本次地形提交前的拆除中触发道路实体26218组件断言，地形提交也触发同一断言；停止后切换干净测试地图。此记录不证明旧存档已修复，也不将异常结果自动重发。

源码更新后需重载游戏桥接；MCP 服务重启/刷新后新工具才会出现在客户端。先看实际能力结果，不能仅凭磁盘版本认定常驻服务已更新。
