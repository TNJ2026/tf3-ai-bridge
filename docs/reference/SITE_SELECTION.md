# 批量设施选址与性能

`find_facility_sites` 在一份已保存的地图快照上批量生成、筛选和排序候选点，适用于停靠点以及仓库、公路站、铁路站等陆地设施的选址初筛。只修改 MCP Server，无须更新游戏桥接；刷新服务连接后可发现工具。

它把大量位置试探放到本地，避免 agent 对每个位置重复读地图或调用原生预览。规划结果仍是候选，不自动建造，也不自动打开 HTML。

## 推荐工作顺序

1. 确认当前会话，调用一次 `capture_planning_snapshot` 采集目标片区，通常使用 25～100 米地形间距。调查边界应包含整个搜索范围及升级预留区。
2. 从资源、原生配置或已有设施调查尺寸。使用相对放置原点的包围框描述当前占地和升级预留区，注明原生尺寸或估算依据。不能假定原点总在建筑中心。
3. 将同一片区的多个选址需求组成 `requests`，调用一次 `find_facility_sites`，默认 `ranking="flat_first"` 优先平整地面。修改筛选条件时复用同一快照，不重复读取游戏。
4. 每项需求默认返回至多 3 个有位置间隔的候选，仅返回候选数据与方案 JSON，不显示中间卡片；最终方案完成后再调用 `export_planning_report`。先比较这些候选，不对搜索网格里的每个点做原生预览。
5. 每项选定一个候选，把其世界坐标 `current/reserved/basis` 传给 `plan_local_development`，核对多个设施之间的冲突及接驳走廊。可将已选定用地作为后续搜索的 `reserved_areas`。
6. 进入施工前重新解析实体、道路类型、端口与覆盖，仅对优选位置按对应建造工具做预览。若报未知碰撞、断言或超时，按执行手册核对现场，不自动连续尝试其他点。

## 输入示例

以下是单个仓库的搜索条件，不是实机尺寸或当前地图坐标。`snapshot_path` 和 `output_dir` 使用本次任务路径。

```json
{
  "requests": [{
    "name": "成品仓库",
    "kind": "facility",
    "target": {"x": 500, "y": 500},
    "radius": 300,
    "step": 25,
    "rotations": [0, 90],
    "current": {"min": {"x": -20, "y": -15}, "max": {"x": 20, "y": 15}},
    "reserved": {"min": {"x": -30, "y": -25}, "max": {"x": 60, "y": 45}},
    "basis": "示例估算，待核对原生模块、出入口和升级尺寸",
    "max_height_range": 5,
    "ranking": "flat_first",
    "min_separation": 50
  }],
  "max_candidates": 3,
  "max_evaluations": 10000,
  "reserved_areas": []
}
```

`current` 和 `reserved` 是局部坐标；工具先旋转再平移，并用保守轴对齐包围框检查。`reserved_areas` 则是已选方案的世界坐标框，两者不能混用。旋转单位为度，高差、距离和间距单位为米。

停靠点使用 `kind="street_stop"`，另传 `edges=[...]`，其中 ID 必须来自快照中已调查为公路的路段。工具沿边的曲线在参数 0.25、0.5、0.75 生成候选，局部 X 方向沿道路切线；忽略通用网格的 step／rotations 设置。仅暂时排除该候选的承载边，其余道路、建筑及其他预留区仍参与避让。返回 `edge/param` 只是后续 `build_street_stop` 预览的定位线索，不能跨改路或换档直接用于建设。

## 筛选、排序与边界

- 同时检查当前建筑和升级／接驳预留区；排除超出调查范围、接触已知障碍、采样含水及超过高差阈值的候选。障碍空间索引只检查附近对象，超大对象单独处理。
- 地形检查包括框内与边界插值所需的网格顶点，避免只查四角漏掉内部水域或高地。粗采样仍可能漏掉小尺度障碍；缺失包围盒也不等于空地。
- 默认 `ranking="flat_first"`：先比较预留范围及给定接路范围是否满足平缓优先条件，再比较最大采样地表坡度、预留区高差和目标距离。接路范围的矩形检查较保守，可能包含实际走廊之外的地形；仍须局部设计及原生检查。返回 `terrain`、可选 `accessTerrain` 和策略版本。
- 可显式使用 `ranking="distance_height"` 保留旧排序：“到 target 的直线距离＋20×采样高差”。`score` 字段继续保存此旧分数以兼容读取，默认排序应按候选数组顺序及 `ranking` 理解，不能按 `score` 重排。两种方式都是初筛启发式，不是建造价格、道路距离、覆盖人口或收益预测。
- `target` 应根据实际服务对象或拟接入位置设置。工具不自动识别需求、最佳出入口、道路连通或城市覆盖；铁路站还须后续工程设计。港口等水域设施暂不支持该陆地筛选流程。
- 每个请求的候选是互斥备选，不是同时建造布局。多个请求之间不自动分配用地，选择后再做局部方案冲突检查。
- 每批 1～20 个请求，每项至多 10 个输出候选；最多 20000 次位置／朝向检查，默认 10000 次。超过预算会明确拒绝，应缩小范围或增大步长；不静默截断后声称已搜索全部范围。
- `searches` 返回各需求的检查数量、拒绝原因、候选与 `no_candidate` 状态。`metrics` 返回候选检查数、障碍检查数、地形顶点数、筛选耗时及 `gameCalls=0`。耗时不包含快照读取和方案文件保存；本工具不渲染卡片。

2026-10-01 离线合成数据测量：7000 个障碍、3586 个位置／朝向检查，筛选约 0.07 秒；同一组 625 个矩形查询与完整扫描结果一致，索引查询（含建索引）约 0.006 秒，完整扫描约 0.93 秒。数值只描述此次本机合成基准，不代表真实游戏调查、原生预览或整体任务提速倍数。当前未进行实机施工验证。
