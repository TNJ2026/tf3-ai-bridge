## 行为

旧GUI会话在第257次非滚动读取请求前拒绝请求，no_gui层随后停止心跳。新版本将每轮256次额度交由引擎持久账本统一管理。额度耗尽只返回带`rejectedBeforeDispatch=true`、`code=operation_quota_rejected`的原生拒绝回执，不执行世界命令，接收器继续心跳、只读查询及额度重置。

纯读取不计额度；预览、改速、车辆、施工等非读取仍计额度。底层接口和现有一次性脚本本身不隐式重置或重跑批次；执行者按用户长期授权主动调用重置入口，再从已读回的实际步骤续作，无需向用户申请。本文更新的是执行策略，不表示所有脚本已内置自动重置。保存通道自身的256次保存限制独立保留，本机制仅重置操作额度。

## 调用

1. 在已授权且未暂停的任务中取得公共工作流锁，读取新鲜`no_gui_status`，核对会话、无主机pending，并确认`operationQuotaVersion=1`。旧接收器拒绝发布重置请求；不以重载或清账本代替重置。
2. 用当前通道查询`get_validation_state`，读取`operationQuota`中的`round`、`used`、`remaining`、`activeRequestCount`、`retiredRequestCount`和`replayIdLimit`。
3. 额度用尽或不足以完成下一组必要操作时，无需用户审批，由执行者调用MCP工具`reset_operation_quota(expected_session, expected_round, expected_used)`，或同名`NoGuiClient`方法。这里的显式调用指具名接口操作，不是再次申请权限。工具再次检查原生状态，发送一次重置，并独立读回新轮次及剩余额度。参数变化、回执异常或读回不符立即停止，不重发。
4. 记录重置前后轮次、已用/剩余额度、操作ID及读回结果，重新解析受影响现场和获取有效预览，再从实际续作点继续。明确`rejectedBeforeDispatch`的额度拒绝不视为施工成功；确认目标未执行后可重新规划该待办。已执行、部分成功或结果未知的提交不得重发，不能重跑整个施工脚本。

原生命令另带`expected_count`，与轮次/已用额度一起做比较，避免读取状态后已有其他操作却错误重置。主机pending、引擎pending/pendingWorkflow、任一未完成请求记录、账目数量不一致、空额度轮次均阻止重置。相关请求失败或未知时仅定向读回原操作，不启动无关历史全量对账；不能用重置清除pending。

## 防重放与容量

重置将本轮已终结请求压缩为持久请求ID记录（包括重置自身和明确拒绝的请求），不会遗忘旧ID；已执行请求跨轮次、引擎重新加载后仍不能再次执行。活跃回执数量清零，历史1024条活跃账本限制不再成为累计操作次数上限。完整主机回执仍由原有`no_gui_history`归档。

重置作废所有构建、线路、道路、设施、编组、移除、工作流预览和临时快照。后续操作必须重新预览。重置不改游戏速度、资金、设施、线路、车辆或机遇，不启动监控，不保存/重载。

历史ID有独立65536条存储保护，上限不能通过重置清零，不自动丢弃防重放记录。因此这不是无限内存/无限运行保证。接近该存储保护时需另行设计与验收归档迁移；不能擅自提高上限或清账本。

## 部署与旧故障

Lua源文件必须原子安装，并首次重新加载存档以载入新的GUI/引擎接收器。仅更新磁盘或重启MCP不能复活已停止的旧GUI接收器；新MCP工具还需客户端刷新工具清单/重新连接服务。加载新版后，后续正常操作额度重置不需要重载。

旧版本已经留下的未知请求不自动当成失败清除。当前盘锦旧请求的拒绝证据见`output/mcp_disconnect_20261011/`，应保留并按原请求对账，不能重放整批购车。监控是否恢复由用户决定，本功能不会改变暂停状态。
