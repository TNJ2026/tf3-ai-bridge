# 游戏贷款接口（始于桥接 0.10.0）

适用于 Transport Fever 3。接口调用游戏原生贷款事件，不直接改账户或账本。借款须在用户授权范围内执行，城市建设授权不自动包含借款。

## 调用流程

1. `get_loans()`：读取当前报价、合同、冷却、余额、贷款数量上限，以及原生算法计算的月供和剩余本金。
2. 借款用 `preview_loan(action="borrow", offer_type="Medium")`；类型必须来自当前报价。还款用 `preview_loan(action="repay", loan_id=0)`；编号必须来自当前合同，示例值不能直接沿用。
3. 核对预览的合同、现金变化和还款负担，在 60 秒内调用一次 `commit_loan(preview_token=...)`。
4. 保存原预览令牌，它也是 `operation_id`。返回未验证或请求超时，调用 `get_loan_operation(operation_id=...)` 核对，不重复提交。

查询和预览不发送贷款事件。提交借款发送 `Loan/Obtain`；提交还款发送 `Loan/Repay`。仅支持游戏当前标准报价，不接受自定义金额或利率。

## 校验与结果含义

| 需要区分的状态 | 判断依据 | 处理 |
|---|---|---|
| 查询／预览 | 仅返回当前数据或拟交易结果 | 核对合同和授权，不代表已经借还款 |
| 提交回调已接受 | 原生命令已被接收 | 继续查操作和合同，不能仅凭回调记账 |
| `verified=true` | 当次合同及现金变化均匹配 | 保存该操作证据与后续月供安排 |
| 未验证、异常或超时 | 无法确认完整交易结果 | 使用原 operation_id 查询；不再提交 |
| 重载后无操作记录 | 内存记录丢失 | 查当前合同与财务账本，不能推定交易未发生 |

- 提交前重新读取合同和报价；贷款状态变化、报价过期或冷却、达到原生数量上限、无限金钱模式、还款余额不足都会拒绝。
- 令牌一次性使用，提交失败也不能重复使用。令牌和操作记录只存在于桥接脚本内存，脚本重载或读档后失效。
- 回调接受命令不代表贷款已生效。只有合同变化与现金变化都匹配，才返回 `verified=true`；成功回执保存的是当时核对结果。
- 未确认操作阻止后续贷款提交。正常经营收入、支出若与交易交错，精确余额校验也可能无法通过；这不等于交易失败。先核对当前合同与游戏财务账本，禁止自动重试或通过重载绕过检查。
- 重载后不能恢复内存操作记录；仍须核对合同和账本，不能因查不到操作而重新借款。

`percentage` 是整个合同的总利息比例，不是年利率。`durationMonths` 使用游戏原生标准记账月，与现实月份无关。提前还款金额依照当前安装版本的原生脚本，只扣剩余本金；不能假设未来版本始终如此。

## 纳入城市发展预算

办理前列出项目完整投资、已有合同月供、运营与维护支出、活动补贴的潜在扣款，以及项目开始收入前所需的现金储备。原生允许借款只说明合同条件满足，不证明所选城市方案能够负担。

借款报价金额和期限以 `get_loans` 为准，不能将预测收入填成实际余额。还款前比较提前归还本金后是否仍能维持已承诺服务；预览与实际提交之间经营现金流可能变化，因此预览余额不是最终到账保证。

发生未知结果时，将该笔交易列为待核对事项，暂停依赖它的后续投资；仍可继续离线方案比较。共享预算的记录方式见[发展方案模板](../strategy/DEVELOPMENT_PLAN_TEMPLATE.md)，并行操作约束见[操作协调](../guides/OPERATION_COORDINATION.md)。

## 验证范围与启用

2026-10-01：17 项贷款专项离线测试覆盖查询、预览、借还款事件负载、一次性提交、报价变化、上限、冷却、余额不足、延迟回执和未知结果。实机只读检查确认查询与预览前后余额、合同数量不变，多档借款报价可预览，余额不足的还款被拒绝。检查脚本为 `scripts/check_loans_interface_readonly.lua`。

实际借款、还款写入尚未在实机存档验证，本次没有执行交易。离线模拟成功不代表已验证原生事件的完整运行时行为。

刷新或重启 MCP Server 以发现新增工具；游戏侧重新载入存档后检查运行桥接与部署代码版本一致且包含贷款接口（最低 0.10.0），再重新查询和预览。旧预览不得沿用。
