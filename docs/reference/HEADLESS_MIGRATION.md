## 通道与会话

`TF3_MCP_TRANSPORT=headless` 将具名 MCP 工具的 `_call` 路由到按需通道；设置了 `TF3_MCP_HEADLESS_MOD` 时默认选择 headless，否则仍默认 file。`TF3_MCP_HEADLESS_MOD` 指向已安装模组的 `content/tf3_mcp_bridge`。现有 MCP 进程须重新启动才能加载 Python 适配代码。

本机桌面配置已补充这两个环境变量和`tool_timeout_sec=600`，并用配置中的`tf3-mcp.exe`原样启动新进程完成实机读取验收。原桌面已启动进程仍缺环境变量，需重新连接TF3 MCP；不需要再次重载游戏。配置备份保留在用户配置目录，其他设置经解析比较未变。字段依据[官方MCP配置文档](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)。当前全图分页与一次运营样本可超过默认60秒，超时仍不授权重发。

请求沿用持久意图、公共进程锁、单个在途请求和原请求 ID 读回。没有文件通道降级、未知结果重发或自动重载。会话变化阻断旧实体操作；调查并对账后使用 `bind_headless_session(expected_session)` 显式绑定，读取玩家、地图指纹并失效主机规划缓存。缓存命中前也检查本地通道会话；后台缓存刷新遇错停止。

具名工具可复用受支持的同名命令；旧施工便捷工具返回新令牌预览，须显式 `preview=True`，随后按对应 `commit_*` 单次提交。旧的 `preview=False` 不会隐式施工。超出新白名单的参数明确拒绝。设施配置仅支持单参数或单模块预览；不是多参数原子配置。`list_vehicles(line=...)` 只在完整列表可确认时本地筛选。旧分页 limit 大于 100 时返回上限 100 的有界页和 `requestedLimit/effectiveLimit` 提示，调用方必须继续分页。

## 组件和整体快照

- `get_entity(id, components)` 支持显式选择 1～16 个组件；`get_component_collection` 支持指定组件字段分页。组件仍以实际加载的原生类型为准。
- `get_planning_snapshot`、`get_route_snapshot` 通过 `begin_snapshot/read_snapshot_page/release_snapshot` 传输冻结 JSON。单份上限 8 MiB，单页最多 24000 原始字节，十六进制封装避免 UTF-8 字符跨页损坏。主机核对令牌、会话、偏移、字节总数及首尾状态，不拼接不同快照。
- 引擎仅保留一份快照，600 秒过期；新快照替换旧快照。失败不自动重新开始。原生整体采集的性能与大小边界仍须实机测量。
- 主机规划与线路缓存可消费原契约；新通道每次刷新取全量冻结快照，暂不使用旧增量 revision 优化。缓存可复用有效窗口内的结果，但不能取代施工前现场复核与原生预览。

## 复杂线路编辑

引擎入口 `preview_line_edit` 接受 `{line, stops}`，2～32 个停靠项。每项二选一：

- `source_index`：引用当前线路的零起始站序，保留该项原生 waypoints、alternativeTerminals 和装载配置，可重排、删减或修改主站台与配置。
- `station_group`：新增停靠项，同时明确 `station`、`terminal`、`loads`；装载配置显式初始化。

可选修改字段为 `station`、`terminal`、`loads`、`max_load`、`force_unload`、`extra_wait`。单项最多 8 个货品，装载比例 0～1，额外等待 0～600 秒。不增加任意新 waypoint/替代终端定义，不接入改名、颜色或每货品独立装载比例。

预览只验证配置和原生终端引用，返回 `configurationOnly=true/pathVerified=false`。`commit_line_stop(preview_token)` 复用现有提交入口：校验会话、60 秒令牌、线路原配置和终端签名，单次提交并读取完整配置核对。路径、客货运实际运行及班距仍需单独验收。异常或部分成功停批，不重放。

## 车辆批次

`execute_vehicle_batch(batch_id, operations, expected_session)` 编排 1～64 个明确的单车操作：购买、分配、停止/恢复、返库和出售。每项为 `{command, arguments}`；购买须 `count=1`，后续分配可用 `purchase_index` 引用前面购买项返回的真实 ID。

批次日志存于桥接目录 `vehicle_batches/<batch_id>.json`。先持久化意图再发送；每步记录请求 ID、结果、独立实体读回。购买核对车库，分配核对线路，停止核对标记，出售核对完整清单。任何未知、部分失败或读回不符终止后续步骤。同一批次 ID 只读原日志，绝不自动续跑；修改参数或会话复用该 ID 会拒绝。返库命令成功不表示已实际到库，日志明确 `arrivalVerified=false`。

公共锁保护每次实际请求和批次 ID 预留，整个多步工作流不是跨进程原子事务；仍须遵守施工协调规则。此接口不授权购车、额外支出或自动重试，调用前仍须核对现场预算和备份。

## 自动接取与只读监控

原 `subvention_autoaccept` 经新适配器运行：预览并再次核对条款，单次接受、独立操作读回。意图和条款在接受前持久化，MCP 重启后保留未知 UID 阻断，另有跨进程策略锁。会话变化需对账，不能复用旧 UID。原评估仅是初筛，不新增保证资源余量、预算或任务必成的能力。不会自动开启。

`operations_monitor(action, interval_seconds)` 提供 `status/run_once/start/stop`。间隔至少 60 秒；明确启动才运行，无重叠、无积压补跑，忙碌或已有在途请求跳过，异常停循环。读取玩家/地图、资金/贷款、机遇、城市实际人口和货品需求、建筑年度消费/交付、分页全量线路与车辆（含在库和未分配）。建筑必须先验证真实 STOCK_LIST 才查消费，同库存去重，无效库存明确未知。

记录新寻路故障、恢复、用户停运、维护低值/恢复、需求和人口门槛变化、机遇状态及负现金。与同会话、同地图前样本比较，保留最新样本用于进程重启后去重；年度统计差不作为每轮流量。监控输出本地轮次和事件，工具本身不发送桌面通知。未接入完整产业配方/库存货龄供需审计、平台占用/班距及资金压力预测，这些在每轮 `unknown` 中明确记录。

监控不施工、购车、改速、保存、修复或接受机遇；自动接取是另外显式启动的功能。旧 tf3/tf3-2/tf3-3 自动化不会因本次实现恢复。直接调用旧 `Bridge/eval` 的历史工程脚本尚未逐个迁移，不能直接重放。
