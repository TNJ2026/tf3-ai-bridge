## 接口

当前通道 `preview_network` 新增可选布尔参数 `connect_road_junctions=true`。调用仍使用当前会话的具名请求及 `commit_network` 单次提交；没有 Lua/eval 回退。主机与游戏的参数校验同步更新。新参数需要当前 MCP 进程重新加载主机代码，游戏接收器须重新加载新版脚本。

仅在起点或终点支持将现有二路节点扩展为三岔口。不支持路段中间自动切分、四岔口、桥隧、轨道/电车、设施冻结节点、建设实体拥有的道路、带站牌等对象的道路、外部玩家道路、自定义转向或信号。原有两条道路须均为普通地面小型/中型双向公路、具有完整交通网络及显式双向车道连接。一次新建的连续道路中间节点实测没有BASE_NODE_CONFIG；此类隐式配置节点不在当前支持范围，不应作为当前适配器的阳性测试用例。

曲线分段仍遵守 `preview_network` 的10～200米跨度、600米总长、地面坡度上限和方向校验。长路先完成两端与走廊的整体设计，再按依赖施工；不要先建孤立道路后临时寻找接入口。

## 同次提交与读回

- 保留原路段、几何、车道、横道及默认信号设置；在同一原生提案中添加新支路并加入新旧路段间完整的双向车道连接。没有先清除节点配置的独立命令，也不以替换路段进行自动刷新。
- 按节点端别转换原生车道索引，兼容每向一条或两条机动车道；保留原有道路之间的转向。预览只操作新建配置对象，不能修改引擎返回的现有组件。
- 预览签名覆盖当前节点位置、两条旧道路完整快照、原有配置和模板。提交前再次读取并比对；60秒单次令牌，拒绝变化或过期结果，不自动重发。
- 建后独立核对旧路未改、新路实体、三路邻接、交通网络、完整车道连接、横道和信号策略。AUTO模式会随新增车道自动生成配时；v34保留并严格核对AUTO、trafficLightType=-1及未自定义标记，另外校验原生配时的有限时长、最小时长、布尔canSkip和无重复且在转向数量范围内的整数lockedLanes。预览身份仍包含完整原配时，不忽略预览到提交的变化。旧组件使用提交前的纯值快照，不能持有已替换组件再读。
- `verified` 只指上述静态读回；`serviceConnectivityVerified=false`、`directedPathsVerified=false` 保持明确。每个旧路与支路的 CAR/TRUCK 双向通路须使用独立 `check_road_junction_path` 请求验收，并检查原有两路间通行。不能把绕行可达视为接入口通达。
- 未知或不一致结果保留 pending 并停止后续修改。旧接口保护及256次防重放限制不变。

## 隔离验收步骤

1. 保留江门当前施工前存档；另存隔离测试槽。经用户确认切换至隔离槽，载入待验收版本，重新绑定新会话并解析地图/目标实体。
2. 在隔离图重新解析现有带显式配置的普通二路节点，核对旧路、配置和完整支路占地后，使用新接口增加中型公路支路。原生预览不得有碰撞或错误；提交一次。无显式配置的全新连续道路不作为此版本的阳性用例。
3. 独立读回配置及新旧道路网络，按方向分开核验 CAR/TRUCK 的全部三路组合；检查保留的横道、原转向及旧路几何。
4. 短时模拟、保存隔离结果。出现原生断言或未知结果立即停止，不重试。
5. 隔离通过后，须恢复已保存的正式现场，重新确认会话，再为养殖场捷径做新工程预览。接口验证通过不代表先前穿坡直线方案可施工。

专项测试：`server/tests/test_ui_road_junction.py`。覆盖双端方向、混合宽度、原生userdata快照、参数拒绝、原配置无别名修改、预览到提交发生变化、配置/旧路/网络读回异常和令牌单次消费。模拟引擎通过不替代原生验收。
