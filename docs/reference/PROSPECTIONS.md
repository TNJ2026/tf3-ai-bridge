# 资源勘探接口

桥接版本：0.12.6。通过游戏原生 `Companies/spawnIndustry` 事件接入，不直接生成产业、不修改许可或公司状态。

## 接口分类

| 工具 | 用途 | 改变游戏 |
|---|---|---|
| `list_prospections()` | 当前经济配置支持的资源、产业类型、解锁/许可/冷却 | 否 |
| `get_prospections()` | 原生任务进度及仍可读取的结果通知 | 否 |
| `preview_prospection(town, resource)` | 核对当前城镇、资源、许可、重复任务；返回60秒一次性凭证 | 否 |
| `commit_prospection(preview_token)` | 重新核对并提交一次原生勘探，返回 operation_id | 是 |
| `get_prospection_operation(operation_id, tracking_receipt)` | 协调提交结果，跟踪排队与成功/失败 | 否 |

`resource` 使用资源列表返回的完整 exploration 路径，不用货物ID或数组下标。`town` 必须从当前地图重新获取。资源匹配沿用原生菜单的经济 placementParams 与 requiredTags；没有匹配产业时 available=false，即使有许可也不提交。

## 执行流程

1. 获取当前地图、资源目录与勘探队列；按供需和运输距离确定目标。
2. 通过游戏原生存档保留操作前状态。
3. 预览选定城镇和资源；提交前重新核对原生许可、共享许可和已有同城同货物任务。
4. 在同一已加载桥接实例中使用凭证提交一次，并保存回执。
5. 读取操作状态；只有原生队列确认登记或新结果通知匹配，verified 才为真。`pending` 仅代表已登记，不代表成功发现。
6. 成功后刷新地图缓存、重新解析新增产业及道路，另行规划接驳、仓储、线路和车辆。

超时、派发错误或无法读回时返回 needs_reconciliation 并阻止继续提交。不能重发；先读取队列、历史通知及地图。任务从队列消失但无匹配通知时为 finished_result_unconfirmed，不能当作成功或失败。通知可能被清除，历史缺失不是没有发生过勘探。

预览和操作索引是桥接实例内状态；模拟推进也可能切换引擎Lua实例。提交后必须保存返回的 tracking_receipt，查询时一并传入，即使内存索引丢失也能只读核对。重载后旧预览凭证失效，不自动重新提交。隔离 eval 加载的只读预览凭证在该次 eval 结束后不可用，不得拿它调用正式 commit 工具。

## 游戏规则

- 游戏选取目标城市附近的合适产地；不承诺精确位置或成功。
- 最大搜索时间从原生 prospectionTimeMs 读取；暂停时不推进。当前版本配置为6个默认月份。
- 保留原生公司等级、许可和冷却要求；无限资金不是绕过许可的开关。
- 蔬菜与谷物共用农场许可。
- 本接口不改GUI临时许可预留；提交期间不要同时在游戏界面发起勘探，以免人工操作与脚本竞争。
