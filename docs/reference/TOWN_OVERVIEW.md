# 城市面板概览只读接口

`get_town_overview(town)`，例如 Wareham 使用 `town=13894`。要求接收器能力 `townOverviewVersion=1`。所有字段在一次引擎读取中采集，不修改线路、建筑、游戏速度或监控。

## 返回结构

每个分项返回 `{available, source, value}`；读取失败则返回 `{available:false, source, reason}`，同时加入 `errors`。`complete` 表示本次实现的全部分项均已读取成功，不代表截图像素核验或无限历史数据。保留真实零、false、空集合，未知不换成零。原生 NaN、不可序列化或截断的数据视为不可用。

| section | 内容 |
|---|---|
| overview | 游戏时间、原生城市状态、人口、容量使用、工作/购物公私交通可达性、六类缓存评分及critical标记、排放功率和分贝 |
| reputation | 城市照顾评分、authorityScore、事件因素、声誉、各事件惩罚、营销是否有效、断开的主连接 |
| delivery | 运送评分、原生等级、按线路/货品的滚动半年送达量和延误量 |
| supply | 各土地用途和各货品面板供需、住宅公共交通使用指标、城市库存与容量 |
| noise | 噪音评分、原生选定土地用途的分区噪音与受影响容量、排放来源分类 |
| pollution | 污染评分、排放来源分类；总量同时见overview |
| bonuses | 加成评分、建设加成（经验增量、交通评分增量、声誉恢复）、原生经验因子、增长等级 |
| happiness | 幸福感评分、不幸福人数/总人数，按城内出行、进出城市且居民/非居民、建筑内、步行、私家车和原生前N条线路分类 |
| traffic | 交通评分、系数1采样的原生交通速度评分与各拥堵等级道路数量 |

## 口径

- 评分保留原生数值，缓存评分与即时计算评分分别返回；不把噪音评分当作分贝，也不把交通评分当作km/h。
- `delivery.deliveries` 的 `{late,total}` 与原生半年窗口一致；`happiness.stats` 的二元组为“不幸福人数、总人数”，并不是幸福百分比。
- 幸福感的线路数量采用原生 `NumLinesForHappinessStats`，返回实际N；不是全图所有线路列表。
- 噪音和污染来源是原生分类统计，不承诺逐实体或逐线路排行。保留原生源数据，不凭名称猜排放。
- Bonuses指城市面板奖励/加成，不是机遇合同奖金；合同仍用机遇接口读取。
- 原生townState在计算评分前转为独立Lua数据，避免getter意外影响游戏缓存。不会调用状态设置、惩罚恢复、营销实施、施工或其他命令。
- 此接口提供当前概览与明细，不提供面板历史曲线的全部采样点。

实现依据：游戏安装目录自带 `api/tealdef/api/engine/util.d.tl`、`base/tealdef/game_mechanics/towns/town_util.d.tl`、`towns.d.tl`、`town_react_util.d.tl`。

## 已知限制与部分结果处理

2026-10-15 最终实测中，`overview.emissionsPower` 的原生返回与文档结构不符，三种有依据的读取方案均未成功。该项返回 `available=false` 并保留原因，因此顶层仍为 `complete=false`。七类面板评分、已有排放统计、分区噪音及来源分类均可读，不应将总标记解释为整个响应不可用。

使用者应逐项检查 `available`，按 `errors` 定位缺失项：可以使用成功读取的数据；依赖缺失字段的结论保持未知。不要填零、推算功率或为同一失败无限重载。接口未验证所有底层字段、所有历史曲线或屏幕像素一致性。
