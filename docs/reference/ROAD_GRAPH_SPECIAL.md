## 加载与共同约束

道路图节点现在可为 1～32 个、显式新边 0～48 条。允许仅切分：单个 `split` 节点配 `edges: []`，不强加无关支路；未参与边且不是切分的孤立节点继续拒绝。按完整道路/设施占地、车道、真实通行路径及保存重载分别验收，不能用离线测试或静态 verified 代替原生运行。

## 带站牌道路中部切分

在 `nodes[i].split` 加 `preserve_objects: true`。目前候选范围为普通地面公路上的既有 STOP_LEFT/STOP_RIGHT 站牌，要求 EDGE_OBJECT、STATION、STATION_GROUP、所属边及服务线路均能独立读取；不包含铁路信号对象、建设实体内部道路或桥隧上的对象。

v37/v38 曾按 EDGE_OBJECT 参数分配子段；v38 实测确认参数保留，v39 改按真实停靠网络锚点投影分配子段；不删除/重建站牌、不创建替代站组、不改运营线路。切分点与每个站牌沿曲线对应点的平面距离至少 20 米，此阈值只是适配器保护，不是通用站牌碰撞尺寸。原生如何投影保留对象的参数和终端引用，必须以隔离实测确认。

提交后逐对象检查：原实体仍在、子路段归属、原始参数、资源和参数、真实停靠锚点与位置/姿态（XY和朝向容差2毫米；模型与网络高度必须同步，另设0.25米垂直保护上限）、原站组、STATION 完整语义以及服务 LINE 配置。终端和步行节点中的旧路段实体引用必须对应新子路段；不能要求旧路段编号原样不变，也不能只检查站牌数量。索引、容量和其他语义不随意改写。失败保留未确认操作，不自动重发。

## 自定义信号与转向路口扩展

既有节点可显式加 `junction: {"extend": "preserve", "phase_duration": 10}`，保留所有既有转向及其禁止关系、横道、信号类型和旧阶段时长。只增加涉及新支路的兼容转向。原路口自定义标志能读取时原样保留，未暴露时不伪造其值。铁路双交分道岔不通过此入口处理。

对自定义或强制启用的信号，旧阶段禁止全部新增转向，然后逐个新增转向附加独立阶段，其余车辆转向及人行横道均锁定。默认新阶段 10 秒，可指定 3～120 秒；最多 64 个阶段，超过范围拒绝。该保守配时服务于正确性验证，后续通行效率仍需运行评估。

信号锁定索引为 **车道连接在前、横道在后**；新增转向后必须平移旧横道索引。自定义信号验收额外比较有序转向列表，不能仅比较排序后的转向集合。

也可用 `junction.signals` 提供完整显式信号方案，便于隔离创建测试路口或明确修改配时：

```json
{"preference":"YES","traffic_light_type":-1,"states":[
  {"locked_lanes":[1],"duration":12,"min_duration":1,"can_skip":true},
  {"locked_lanes":[0],"duration":12,"min_duration":1,"can_skip":true}
]}
```

示例仅适用于两个转向且无横道的路口，不能直接用于其他节点。锁定索引从 0 开始；阶段必须有有限合法时长、唯一有效锁定索引和布尔 can_skip。非 -1 信号资源索引须在当前原生仓库存在。生成转向使用确定顺序，预览返回每个节点的转向数量、横道数量和自定义信号标志。

## 既有桥梁与隧道切分

在 `split` 加 `allow_structure: true`，核对原结构类型和当前桥/隧道资源。按原三次 Hermite 曲线精确细分，保留子路段的类型、资源、车道、样式、装饰及街道优先权字段。先验收无支路的纯切分，再独立评估分支，不能用纯切分通过推断桥上路口或隧道岔口均可建。

仍拒绝建设实体内部结构、带对象的结构切分和未知结构资源。结构支撑、洞口、净空、碰撞、双向通路和保存重载需在隔离现场读回/实测。

## 铁路平交

在新建或切分产生的交点节点上指定 `crossing_resource`，资源从 v37 `list_road_structures().crossing` 返回。候选使用原生 `SimpleStreetProposal.node2rcType`；只有显式包含交点资源时允许道路图含 TRACK 模板或读取铁路段。

每个交点严格要求两段公路、两段铁路、相同地面高程，路/轨各自平顺贯通，交角约 45～135 度，节点切线坡度不超过 3%。不支持把 XY 重叠视为连接、不支持桥隧平交、不在既有自定义轨道道岔上接入。

铁路与公路的交点连接交由原生引擎生成，不创建火车转向汽车道路的显式连接。提交后通过 `railRoadCrossingSystem.getRailroadCrossingForNode` 查真实平交实体，核对 RAILROAD_CROSSING 类型及四条实际邻接边；汽车、货车和列车各自正反向通路必须独立查询。列车通过时的道口开闭和汽车让行仍需实际运行验证。

## 本轮原生验收顺序

1. 核对候选加载、隔离存档、暂停、新会话和资源；重新勘探，旧编号仅作历史索引。
2. 复用已验收桥、隧道样例，读回几何、资源和两向路径。当前桥梁单段纯切分通过；两段隧道须按已验证样例联合切分，先前单段隧道方案被拒绝，不自动重试。
3. 新建小型显式配时路口，读回；增加一支路，验证旧阶段、旧转向限制、横道索引和新增转向阶段。
4. 先建独立公路/铁路十字平交，核对实际平交组件和模式；再测对既有路/轨中部切分的平交接入。
5. 对隔离环路线带双侧站牌路段切分，完整比较对象/站组/线路/终端/步行引用，再增加支路并安排测试车辆。
6. 小批短时模拟、暂停复查并保存；重载单独授权，一次合并验证四类。任何未知错误立即停批、核对现场，不自动重发。

本地原生定义依据：游戏 `api/tealdef/api/type.d.tl`、`api/tealdef/api/engine.d.tl`、`api/tealdef/api/engine/system.d.tl`，以及 `gui.zip/gui/entity_window/double_slip_switch.tl`。在线同源说明：[SimpleStreetProposal](https://wiki.transportfever3.com/script-doc/api/type.html#SimpleStreetProposal)、[RailroadCrossing](https://wiki.transportfever3.com/script-doc/api/engine.html#Engine.Component.RailroadCrossing)。接口字段存在不代表任意提案安全。

## 2026-10-11 v40 候选：六项合并验收

以下记录v40新增接口；最初安装时尚未实测，最新六项限定现场及重载通过结果见末节。主机要求实际心跳 `roadGraphVersion=40`。

- `split.preserve_crossings: true`：切分既有平交的公路或铁路邻边，保留真实平交资源及四臂拓扑；仅重映射替换边，不允许增减交点支路。
- `split.preserve_tunnel_chain: true`：须同时启用 `allow_structure`，仅适用于隧道。将连续同资源隧道纳入单次替换，目标段细分，邻段保持几何；最多16段，仍受48条提案边上限约束。拒绝对象、建设所有边、未知资源和隧道分支。用于复测旧单段碰撞，不宣称已证明原生内部根因。
- 新坐标节点可提供 `junction.blocked_turns: [{from_edge: 0, to_edge: 2}]` 和 `junction.crosswalk_edges: [0]`，索引为显式 graph.edges 的零起始索引；必须附显式 signals，不能用于既有/切分节点或与 extend 混用。转向按整对边的兼容车道禁止，横道要求原生双向步行车道。后续扩展继续保留禁行、旧阶段及横道索引语义。
