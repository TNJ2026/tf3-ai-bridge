# Transport Fever 3 MCP

将用户目标落实为当前地图上的可验证结果。本 skill 不授予额外施工、融资、拆迁、读档或后台监控权限。

## 入口

- 首次配置、工具不可用、换安装来源或连接失败：读 [连接与首次验证](references/connection.md)。
- 查询、规划、建造、购车、装卸或运营故障：读 [日常操作](references/operations.md)。
- 定位用户提供或工作区中的 TF3 AI Bridge 项目根目录（含 `server/`、`mod/`、`docs/`），读取适用 `AGENTS.md`。参考文档路径相对项目根目录，不固定个人磁盘路径、Steam 用户、mod.io 编号或地图 ID。
- 项目未定位但 MCP 可用时，可先按工具 schema 只读检查连接，不为查状态重装模组。需要配置或缺少关键规则时，再定位源码或询问缺失路径。
- 当前工具 schema、实时能力和当前有效规则优先于历史示例。公共源码可能没有 `output/`、`exports/` 历史证据；不能假造已验收结论或执行旧脚本补证。

## 每次开始游戏工作

1. 发现 TF3 MCP 工具并调用 `bridge_status`，核对心跳新鲜度、实际版本、接收器代次、模式、会话、主机和未决状态。
2. 确认地图、玩家和必要能力。新会话使用受支持绑定流程，重新取得实体 ID；旧预览与缓存不能跨地图复用。
3. 按目标选择最小调查范围。只规划不施工；已有实施授权则直接推进到相应验收，不重复索要授权。
4. 先核对已提交工程进度，再新增操作。未知结果先冻结相关写入、核对原请求，不清 pending、不重放请求或历史脚本。

## 交付

区分连接可用、配置写入、实体建成、实际投运、城市收货和合同原生完成，只报告有证据的阶段。心跳在线、`ok=true`、车辆无寻路错误和工程 `complete=true` 含义不同。

在本地任务记录保存必要的会话/地图标识、工程和请求 ID、已完成步骤、资金承诺及续作点。私人路径、作者信息、凭据、实际配置和运行账本不加入公开仓库。

创建或阅读 skill 不启动游戏操作或恢复监控；监控仅按用户要求及平台调度能力建立，保留用户暂停和通知偏好。
