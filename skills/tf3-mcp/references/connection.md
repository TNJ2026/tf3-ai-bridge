# 连接与首次验证

## 两端与资料

模组与本地 Python MCP 服务是两个组件。游戏必须运行、启用模组并载入地图；模组不内置 AI 模型，也不会自动配置客户端。当前生产通信名是 `no_gui`，不是旧 `headless` 或已移除的 `file`；它表示不用手动操作桥接面板，不代表游戏无需窗口。

优先读项目 `docs/guides/FIRST_CONNECTION.md`（首次连接完整指南），再按需读 `docs/reference/TRANSPORT_CHANNELS.md`；mod.io 下载版再读 `docs/reference/MODIO_CONNECTION.md`。旧项目没有完整指南时沿用本参考流程。不要从历史实验记录恢复旧探针或通道。

## 自动发现模组目录

按以下顺序缩小范围，不默认全盘扫描，也不要求用户一开始就提供路径：

1. 检查目标 MCP 服务配置中的 `TF3_MCP_NO_GUI_MOD`，只读取必要字段，不输出其他服务的凭据；验证目标目录和 `bridge.script.lua` 是否存在。已有路径也可能过期。
2. Windows 下载版优先检查 `%PUBLIC%/mod.io/`（常见为 `C:/Users/Public/mod.io/`），在其下用 `rg --files` 查找 `content/tf3_mcp_bridge/bridge.script.lua`。游戏/模组数字编号仅是候选定位信息，不硬编码历史编号。
3. 在实际 Steam 安装目录的 `userdata/<用户>/3493540/local/` 定位本次游戏日志，按修改时间和会话确认新鲜度。搜索 `tnj_tf3_ai_bridge`、`ModHubMod`、`modHubId`、`source: mod.io`，将日志来源与候选目录对应；历史日志不代表本次加载。
4. 同时检查当前用户 `local/mods/` 是否有同 mod ID 本地副本。源码和 staging 发布副本不能直接当作已加载副本；多个 Steam 用户或多个候选时用本次日志判别，不取第一个目录、不自动删除冲突副本。
5. 配置候选路径后，用实时桥接版本、接收器代次/模式和当前日志交叉核对，再完成真实只读往返。版本相同不足以区分相同版本的多个副本。

没有候选时再根据客户端配置或游戏日志发现其他安装根目录；仍无法定位或来源有歧义时，才询问安装目录/当前用户。非 Windows 环境不得套用 Windows 路径。保存已验证路径到本地配置，后续优先复用；更新、迁移、来源切换或失联时重查。

## 配置

**安装件保护（强制）：** 连接、配置、验证或排查连接问题不授权修改游戏安装件。禁止把项目 `mod/` 或暂存副本复制、同步、覆盖到下载目录，禁止运行会改写下载件的安装器，禁止自动删除冲突副本。路径错误应修正 MCP 配置，不通过改写模组解决。只有用户已明确授权修改安装件以修复或更新模组，且目标和变更已核实时才可执行；已有授权不重复申请。缺少授权先完成只读诊断并给出具体修改方案，再请求授权。修改前在模组外备份、保留未决请求证据，使用正式接收器配置，修改后重新加载并只读验收；不把本地修复声称为已发布更新。详细流程见项目 `docs/guides/FIRST_CONNECTION.md` 的安装件保护。

1. 检查 Python、uv、`server/pyproject.toml` 和 `.mcp.example.json`。当前要求 Python 3.11+；优先复用健康环境，需要安装时在 `server/` 执行 `uv sync`，正常使用无需测试依赖。
2. 确定实际加载来源及目录，结合安装文件、当前游戏日志和实时接收器代次核对。下载目录存在不代表已加载；同 mod ID 本地副本可能遮蔽下载版。列明冲突，不擅自删副本。
3. 按所用客户端的配置格式添加标准输入输出服务，只改目标服务，保留其他配置。下面路径必须替换为本机实际值：

```json
{
  "mcpServers": {
    "tf3": {
      "command": "uv",
      "args": ["--directory", "<项目绝对路径>/server", "run", "tf3-mcp"],
      "env": {
        "TF3_MCP_TRANSPORT": "no_gui",
        "TF3_MCP_NO_GUI_MOD": "<实际安装模组>/content/tf3_mcp_bridge"
      }
    }
  }
}
```

`TF3_MCP_NO_GUI_MOD` 指向 content 内目录，不是源码根目录或模组外层。必要时设 `TF3_MCP_DIR` 为本地账本目录；不要复制他人 Steam ID。`TF3_UI_LANGUAGE` 可设 `zh-CN`、`en`、`auto`。实际配置不提交 Git。

4. 正式下载包应已启用 userdata，不默认覆盖安装件。开发目录一般 demand；indexed 是有限兼容模式，不作长期默认。安装器 auto 是选择规则，不是第四种模式。
5. 仅在确认接收器缺失/过旧且任务包含安装修复时，查看 `scripts/install_no_gui_diagnostic.py --help`，按当前文档备份、编译检查和原子替换。下载版使用 userdata，不用 demand 绕过资源发现限制，不用默认关闭接收器的开发源码覆盖正式包。
6. 配置/Python 变更需重连 MCP；Lua 接收器变更需重载地图。磁盘更新不等于内存更新。首次激活通常需用户进入地图，失效连接不能自举读档。保存/读档须符合当前授权与 `docs/reference/LOAD_GAME.md`，不自动丢弃进度。

## 最小只读验收

1. `bridge_status` 核对新鲜心跳、模式、版本、代次、会话、主机、pending 和切换状态。服务启动、工具出现仅证明客户端能启动服务。
2. 状态要求绑定时，读取 `bind_no_gui_session` 当前 schema，使用新鲜的精确 `expected_session`，随后独立确认状态和地图。绑定不用于清未知写入。
3. 实时能力支持 `readBatchVersion` 后，使用 `read_planning_data` 做真实往返：

```json
{"requests":[
  {"command":"get_game_state","arguments":{}},
  {"command":"get_map_info","arguments":{}},
  {"command":"list_towns","arguments":{"limit":3}}
]}
```

逐项检查 ok 与子结果 available/complete；下一轮详情使用真实城市 ID。心跳新鲜不能替代请求成功。
4. 报告实际版本/来源、会话和读取结果及未验证能力。连接验收不购车、借款、施工、保存读档、改速或恢复监控。

## 故障定位

| 现象 | 处理 |
|---|---|
| 没有 MCP 工具 | 检查客户端配置、uv 路径、源码目录、依赖与启动错误；需要重连时说明 |
| 心跳过期或无地图 | 查游戏载入、模组激活和当前日志，不发送施工 |
| 心跳新鲜但读不通 | 查实际来源、模式及路径，尤其下载版是否误用 demand |
| 磁盘与实时版本不符 | 查副本遮蔽或未重载，不把改磁盘当作修复完成 |
| 会话变化 | 核对地图、主机及 pending 后按受支持流程绑定，作废旧实体/预览 |
| 超时或未知结果 | 保留请求 ID、日志锚点和账本，查原回执，不重发、不删信箱账本、不以重启清锁 |

优先具名诊断工具，有明确安全恢复路径才继续；否则报告阻碍、已知影响和恢复条件，保留现场。
